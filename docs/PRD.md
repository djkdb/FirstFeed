## 1. 배경 — 왜 만드는가

### 1-1. 시작 이야기
올해 8월 Claude Max를 쓰기 시작하면서, 원래 관심이 많던 AI로 이것저것 만들어 보았다. 결과물이 쌓이자 **혼자 보기엔 아깝다**는 생각이 들었고, 해 온 것들을 정리해 보고 싶어 인스타 계정을 만들어 운영하기 시작했다.

- **한 달 만에 팔로워 1,500명**
- 이 계정을 계기로 **네이버 AI 디깅클럽**, **행정안전부 주관 청년 공공 AX 서포터즈** 등 대외활동 참여, 협찬 제안도 받기 시작

운영하면서 얻은 결론은 하나다.
> **AI로 누구나 비슷한 결과물을 만들 수 있는 시대에는, "나는 누구인가"를 분명히 하고 내 개성을 브랜딩해 남들과 다르게 보이는 것이 가장 중요하다.**

그리고 처음 시작하는 사람에게는 바로 그 부분이 가장 어렵다.

### 1-2. 문제 정의 — 직접 겪은 다섯 단계
| # | 단계 | 무엇이 막히는가 | 결과 |
|---|---|---|---|
| P1 | 시작 | **무슨 계정인지 모른다** — "IT 정보", "일상" 같은 넓은 말로 시작 | 10개쯤 올리면 소재가 떨어지고, 계정 색깔이 흐려진다 |
| P2 | 디자인 | **보이는 게 매번 다르다** — 게시물마다 색·폰트·구도가 다름 | 프로필 격자가 한 사람의 계정처럼 안 보인다 |
| P3 | 소재 | **무엇을 올릴지 매일 고민한다** — 남의 잘 된 콘텐츠를 보면 따라 하고 싶지만 내 계정과 맞는지 모름 | 일관성이 깨지거나, 올리는 간격이 벌어진다 |
| P4 | 성과 | **숫자를 봐도 뭘 바꿔야 할지 모른다** | 같은 실수를 반복한다 |
| P5 | 성장 이후 | **관리 자체가 일이 된다** — 대외활동 미션 마감, 협찬 원고 일정, 필수 표기(#협찬)가 카톡·메일·노션에 흩어짐 | 마감을 놓치거나 표기를 빠뜨린다 |

### 1-3. 기존 도구의 한계
| | 정체성 정의 | 일관된 디자인 | 소재 발굴 | 콘텐츠 생성 | 성과 → 다음 행동 | 대외활동·협찬 관리 | 단계 간 연결 |
|---|---|---|---|---|---|---|---|
| Canva | ✕ | △ 템플릿만 | ✕ | △ 수작업 | ✕ | ✕ | ✕ |
| Later · Metricool | ✕ | ✕ | ✕ | ✕ | △ 숫자만 | ✕ | ✕ |
| ChatGPT 등 범용 AI | △ 매번 새로 | ✕ | △ | △ 형식 들쭉날쭉 | △ | ✕ | ✕ 기억 없음 |
| 노션 · 캘린더 | ✕ | ✕ | ✕ | ✕ | ✕ | △ 직접 입력 | ✕ |
| **퍼스트피드** | ○ 근거 기반 | ○ 고정 템플릿 | ○ 내 축 기준 | ○ 카드·릴스·캡션 | ○ 프로필 갱신 | ○ 원문 → 자동 정리 | **○ 브랜드 프로필 하나로** |

### 1-4. 고유한 가치 (차별점)
1. **한 장의 브랜드 프로필이 모든 단계를 잇는다** — 정체성 → 디자인 → 소재 → 생성 → 성과 → 다시 정체성으로 도는 순환
2. **근거 기반** — 정체성의 축은 사용자가 말한 근거에서만, 콘텐츠의 숫자·이름은 소재 원문에서만. 원문에 없으면 코드가 되돌린다
3. **내 AI 구독으로 돈다** — 별도 결제 없이, 이미 쓰는 Claude · ChatGPT(Codex) · Gemini 구독을 엔진으로
4. **시작부터 성장 이후까지** — 계정이 커지면 생기는 대외활동·협찬 관리까지 같은 곳에서

## 2. 목표와 범위

### 2-1. 목표
| 구분 | 목표 |
|---|---|
| 사용자 | 처음 쓰는 사람이 **30분 안에** 브랜드 프로필 + 고정 템플릿 + 첫 카드뉴스 1세트를 얻는다 |
| 품질 | 생성된 콘텐츠가 규칙 검증을 **재작성 2회 이내**에 통과한다 · 소재에 없는 숫자·이름 **0건** |
| 운영 | 대외활동·협찬 공지에서 뽑은 마감일 정확도 **90% 이상**(테스트 공지 30건 기준) |
| 대회 | 중간: 정체성 → 브랜딩 → 템플릿 고정 → 카드뉴스 1세트 시연 · 최종: 전 기능 시연 + 실사용자 2~3명 사례 |

### 2-2. 범위에 넣는 것
- 정체성 찾기 · 브랜딩 키트 · 템플릿 고정 · 발굴 탭 · 만들기(카드뉴스 · 릴스 대본/표지 · 릴스 영상 · 캡션/고정댓글/DM) · 발행(준비 + 공식 API 예약) · 성과 루프 · 대외활동·협찬 대시보드
- 사용자 여러 명(로그인) + 한 사용자의 브랜드 여러 개
- AI 공급자 3종(CLI) + API 키 대체

### 2-3. 범위에 넣지 않는 것 (비목표)
- **인스타 비공식 자동화** — 로그인 세션 조작, 스크래핑, 자동 팔로우·좋아요·댓글. 계정 정지 위험이 있고 정책 위반
- AI 이미지 **직접 생성** — 그림은 **프롬프트만 뽑아** 사용자가 다른 도구에서 만든다 (2-4 참고)
- 인스타 외 플랫폼 발행 (블로그·유튜브 등)은 이번 대회 범위 밖
- 결제·구독 판매

### 2-4. 확정된 결정 (질의응답 결과)
| 항목 | 결정 |
|---|---|
| 형태 | 로컬 앱 + 선택형 클라우드 동기화 |
| 사용자 | 로그인 여러 명 + 사용자당 브랜드 여러 개 |
| AI | Claude Code · Codex · Gemini CLI 모두 지원, 기본은 본인 구독, 없으면 API 키 |
| 발행 | 기본은 업로드 준비, 공식 API를 연동한 사람은 예약 발행 |

| 이름 | 퍼스트피드 (FirstFeed) |
| 중간 시연 | 정체성 → 브랜딩 → 템플릿 고정 → 카드뉴스 1세트 |

## 3. 사용자

### 3-1. 페르소나
| 페르소나 | 상황 | 가장 원하는 것 |
|---|---|---|
| **민지 (대학생 · 입문)** | 공모전·대외활동에 쓸 포트폴리오 겸 계정을 시작하고 싶다. 디자인 툴은 못 다룬다 | "내가 뭘 올려야 하는지"와 "예쁘게 보이는 틀" |
| **도윤 (사이드 프로젝트 운영자)** | 만든 앱을 알리고 싶은데 매번 홍보물을 만들 시간이 없다 | 소재 → 카드뉴스·릴스까지 자동, 일관된 디자인 |
| **서연 (성장 중인 크리에이터 · 팔로워 1천~1만)** | 서포터즈 2개 + 협찬 3건을 동시에 굴린다 | 마감·필수 표기 놓치지 않기, 무엇이 먹혔는지 숫자로 |

### 3-2. 핵심 사용자 여정
```
[처음]  가입(선택) → AI 연결 확인 → 정체성 찾기(설문 → 인터뷰 → 자료) → 브랜드 프로필 확정
        → 브랜딩 키트(이름·바이오·색·폰트·프로필/하이라이트 프롬프트) → 템플릿 시안 비교 → 고정
        → 발굴 탭에 주제·피드·참고 계정 등록 → 첫 소재 고르기 → 카드뉴스 1세트 → 업로드 폴더
[매주]  발굴 탭에서 소재 고르기 → 만들기(카드/릴스) → 검토·수정 → 예약 또는 업로드
[성장]  대외활동·협찬 공지 넣기 → 마감순 대시보드 → 미션 원고를 만들기로 → 필수 표기 검사 → 발행
[돌아보기] 성과 연결 → 무엇이 먹혔나 → 브랜드 프로필 갱신 제안 → 다음 소재 추천에 반영
```

## 4. 기능 요구사항

> 표기: **FR-영역-번호**. 우선순위 **M**(중간 발표까지 필수) · **F**(최종까지) · **S**(여유 있으면)
> 각 기능은 "사용자는 … / 시스템은 …" 과 **수용 기준(AC)** 으로 정의한다.

### 4-0. 공통 · AI 연결 (FR-AI)
| ID | 요구사항 | 우선 | 수용 기준 |
|---|---|---|---|
| FR-AI-1 | 시스템은 첫 실행 때 컴퓨터에 설치된 AI CLI(Claude Code · Codex · Gemini CLI)를 찾아 **로그인 상태까지** 확인하고, 사용할 공급자를 고르게 한다 | M | 설치·로그인 여부가 공급자별로 표시된다. 아무것도 없으면 설치 안내 또는 API 키 입력으로 이어진다 |
| FR-AI-2 | 모든 AI 호출은 **공급자 어댑터** 한 곳을 거친다 (요청: 프롬프트 + JSON 스키마 + 첨부 이미지 + 웹 검색 여부 → 응답: 검증된 JSON) | M | 같은 기능을 공급자만 바꿔 돌려도 같은 형식의 결과가 나온다 |
| FR-AI-3 | 공급자마다 가능한 것이 다르면(웹 검색, 이미지 읽기) **능력표**로 판단해 안 되는 기능은 대체 경로로 보낸다 (예: 웹 검색 불가 → RSS만) | F | 능력표가 화면 설정에 보이고, 대체 경로로 간 경우 사용자에게 한 줄로 알린다 |
| FR-AI-4 | AI 출력은 **생성 → 규칙 검증(코드) → 자기 평가(AI) → 재작성** 루프를 거친다. 최대 재시도 횟수는 설정값 | M | 규칙을 통과하지 못한 결과는 저장되지 않는다. 재시도 이력이 로그에 남는다 |
| FR-AI-5 | 사용량 표시 — 이번 작업에 AI를 몇 번 불렀는지, 오래 걸린 단계는 어디인지 | S | 작업 상세에 호출 수·소요 시간이 보인다 |

### 4-1. 정체성 찾기 (FR-ID) — P1 해결
| ID | 요구사항 | 우선 | 수용 기준 |
|---|---|---|---|
| FR-ID-1 | **짧은 설문** — 사용자는 전공/직업, 관심 분야(복수), 계정 목표(포트폴리오·홍보·수익·기록), 주당 올릴 수 있는 횟수, 얼굴 노출 여부, 보여줄 수 있는 것(만든 것·공부·일상·리뷰 등)을 고른다 | M | 2분 안에 끝나는 10문항 이내 |
| FR-ID-2 | **AI 인터뷰 채팅** — 시스템은 설문에서 비어 있거나 모호한 부분만 골라 꼬리질문 5~10개를 한다. 한 번에 한 질문, 예시 답 제공 | M | 같은 질문을 두 번 하지 않는다. "잘 모르겠어요"에는 선택지로 다시 묻는다 |
| FR-ID-3 | **내 자료 올리기** — 포트폴리오 PDF, 이력서, 깃허브 주소, 블로그 주소, 기존 게시물 캡처를 올리면 근거로 쓴다 | F | 자료에서 뽑은 근거 문장이 출처(파일명·쪽)와 함께 보인다 |
| FR-ID-4 | 시스템은 **브랜드 프로필 초안**을 만든다: 계정 정의 한 줄, 타깃, 콘텐츠 축 3~5개(축마다 근거 인용), 말투 규칙, 피할 것, 모르는 것 목록 | M | **근거를 인용할 수 없는 축은 만들지 않는다.** 축끼리 의미가 겹치면 다시 쓴다 |
| FR-ID-5 | 사용자는 초안의 문장을 직접 고치거나, 축을 빼고/더하고, "다른 방향 2개 더"를 요청할 수 있다 | M | 수정 이력이 남고 이전 판으로 되돌릴 수 있다 |
| FR-ID-6 | 확정한 프로필은 **이후 모든 생성의 입력**이 된다 (말투·축·피할 것) | M | 프로필을 바꾸면 이후 생성 결과에 반영된다 |

### 4-2. 브랜딩 키트 (FR-BR) — P2 해결
| ID | 요구사항 | 우선 | 수용 기준 |
|---|---|---|---|
| FR-BR-1 | 계정 **이름(아이디) 후보·표시 이름·바이오** 후보를 각 5개 제안 (바이오 150자 제한, 링크 자리 고려) | M | 글자 수 초과 없음. 바이오가 계정 정의와 축을 담는다 |
| FR-BR-2 | **색 팔레트**(주색·보조·강조·배경·글자) 3안 제안 | M | 글자/배경 명암비 **4.5:1 이상**을 코드가 검사, 미달 조합은 내지 않는다 |
| FR-BR-3 | **폰트 조합**(제목·본문) 3안 — 상업적 사용 가능한 무료 한글 폰트 목록에서만 | M | 라이선스 정보를 같이 표시 |

## 6. 시스템 구조

### 6-1. 전체 그림
```
┌──────────────────────── 사용자 컴퓨터 (로컬 앱) ────────────────────────┐
│  웹 화면 (React)  ←→  로컬 서버 (Node/TypeScript, localhost)              │
│                         ├─ AI 어댑터 ── Claude Code CLI / Codex CLI / Gemini CLI / API 키 │
│                         ├─ 렌더러 ── Playwright(HTML→PNG) · ffmpeg(영상) · OS 음성  │
│                         ├─ 수집기 ── RSS · 웹 검색(AI) · 인스타 공식 API · Gmail/IMAP │
│                         ├─ 검증기 ── 글자 수·근거 대조·명암비·넘침·필수 표기       │
│                         └─ 로컬 DB (SQLite) + 파일 폴더                         │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ (로그인한 경우만)
                     Supabase: Auth · Postgres · Storage · 예약 발행 크론
```

### 6-2. 기술 선택과 이유
| 영역 | 선택 | 이유 |
|---|---|---|
| 화면 | React + TypeScript + Vite | 빠른 개발, 폰에서도 열리는 반응형 |
| 로컬 서버 | Node.js + TypeScript (Fastify 또는 Hono) | CLI 하위 프로세스·파일·Playwright를 한 언어로 |
| 로컬 저장 | SQLite | 설치 없이 파일 하나, 동기화 전에도 완결 |
| 카드 렌더링 | HTML/CSS 템플릿 → Playwright 캡처 | 디자인을 코드로 관리, **넘침을 브라우저가 측정** |
| 영상 | HTML 장면 → 프레임 → ffmpeg | 장면 틀을 카드와 같은 기술로, 결과가 매번 같게(시간을 코드가 넘김) |
| 음성 | macOS `say`(한국어) · Windows 음성 / 선택: fish.audio 등 | 기본 무료로 바로 동작 |
| 동기화·로그인 | Supabase (Auth · Postgres · Storage · Edge Functions + cron) | 로그인·DB·파일·예약 실행을 한 곳에서, 무료 한도로 충분 |
| 패키징 | macOS 앱 번들(더블클릭 실행) → Windows 실행 파일 | 터미널 없이 시작 |

### 6-3. AI 어댑터 설계
- **입력**: `{task, prompt, schema, images[], web: bool, timeout}`
- **처리**: 공급자별 CLI를 비대화형 모드로 실행 → 출력에서 JSON 추출 → 스키마 검증 → 실패 시 깨진 JSON 복구 시도 → 그래도 실패면 재요청
- **능력표**: 공급자별 웹 검색 · 이미지 읽기 · 최대 입력 길이 · 평균 응답 시간을 첫 실행 때 시험 호출로 측정해 저장
- **도구 권한 최소화**: 웹 검색이 필요한 호출에서만 검색 도구를 열고, 파일 쓰기·명령 실행 도구는 열지 않는다
- **시간 제한**: 일반 호출과 웹 검색 호출의 제한 시간을 따로 둔다 (검색은 1~3분 걸림)

## 7. AI · 프롬프트 설계

### 7-1. 원칙
1. **역할보다 기준** — "당신은 마케터"보다 "피드를 넘기던 사람이 1초 안에 멈추는가" 같은 판단 기준
2. **출력은 JSON 스키마 고정** — 칸 이름·개수·글자 수를 코드가 검사
3. **지어내기 방지는 코드로** — 숫자·이름을 원문과 대조, 근거 인용을 필수 칸으로
4. **모르면 비우게** — 근거 없는 칸은 비우고, 빈칸이 많으면 사용자에게 추가 질문
5. **반려는 깨질 때만, 취향은 경고로** — 카드가 깨지거나 사실이 틀리면 재작성, 말투 취향은 경고만 (재작성 비용 절약)
6. **예시는 하나만 주지 않는다** — 하나만 주면 모든 결과가 그 틀을 따라 한다

### 7-2. 프롬프트 목록 (파일로 분리 · 버전 관리)
| 파일 | 하는 일 | 출력 |
|---|---|---|
| `identity_followup` | 설문의 빈칸을 보고 다음 꼬리질문 1개 | `{question, why, examples[]}` |
| `identity_profile` | 설문 + 인터뷰 + 자료 → 브랜드 프로필 | `BrandProfile` 스키마 |
| `brand_kit` | 프로필 → 이름·바이오·팔레트·폰트·그림 프롬프트 | `{handles[], bios[], palettes[], fonts[], image_prompts[]}` |
| `discover_pick` | 후보 묶음 → 축 적합도·알맹이 | `[{id, fit, kernel, reason}]` |
| `cover_titles` | 소재 → 표지 제목 6개 | `[{title, why}]` |
| `card_body` | 소재 + 프로필 + 배치 문법 → 본문 카드 | `{cards[], cta}` |
| `card_review` | 카드 + 소재 → 자기 평가(점수·고칠 곳) | `{score, issues[]}` |
| `reel_script` | 소재 → 훅·장면·대사·자막·촬영 목록 | `{hook, beats[], cover_title}` |
| `caption_set` | 콘텐츠 → 캡션·고정댓글·DM | `{caption, pinned, dm, hashtags[]}` |
| `insight_read` | 인사이트 캡처 → 숫자 | `{reach, saves, ...}` + 읽은 위치 |
| `insight_advice` | 성과 표 → 다음 행동 3개 | `[{do, evidence_numbers[]}]` |
| `task_extract` | 공지 원문 → 할 일 | `[{title, due_at, deliverable, required_marks[], submit_url, quote}]` |

### 7-3. 예시 — 정체성 프로필
```
아래는 인스타를 처음 시작하려는 사람의 설문·인터뷰·자료다.
답변에 근거가 있는 것만 사용해 브랜드 프로필을 JSON으로 만든다.
- account_line: 누구에게 무엇을 주는 계정인지 한 문장 (30자 이내)
- audience: 이 계정을 볼 사람 한 문장
- pillars: 콘텐츠 축 3~5개. 축마다 근거 문장을 원문 그대로 인용(evidence)
- voice_rules: 말투 규칙 3개 / avoid: 피할 것
- unknown: 정보가 부족해 정하지 못한 것 (지어내서 채우지 말 것)
근거를 인용할 수 없는 축은 만들지 않는다. 축끼리 겹치면 하나로 합친다.
```
→ 코드 검사: evidence 문장이 입력에 실제로 있는가 · 축 개수 · 글자 수 · 축 간 유사도

### 7-4. 예시 — 공지 → 할 일
```
아래는 대외활동 운영진 공지 또는 협찬 가이드 원문이다 (작성일: {posted_at}).
할 일을 JSON 배열로 뽑는다: {title, due_at(YYYY-MM-DD HH:mm), deliverable, required_marks[], submit_url, quote}
- quote 에는 근거가 된 원문 문장을 그대로 넣는다
- 상대 날짜는 작성일 기준으로 바꾸고, 바꿀 수 없으면 due_at 을 비운다
- 원문에 없는 내용은 만들지 않는다
```
→ 코드 검사: quote가 원문에 있는가 · 날짜 형식 · 이미 지난 마감인가

### 7-5. 품질 측정 (프롬프트 개선의 근거)
- **고정 테스트 세트**: 인터뷰 답변 5명분 · 소재 20개 · 공지 30건 · 인사이트 캡처 10장
- 프롬프트를 바꿀 때마다 같은 세트로 돌려 **규칙 통과율 · 재작성 횟수 · 원문 밖 숫자 수 · 마감일 정확도**를 표로 비교 → 최종 발표의 "프롬프트 엔지니어링 과정" 자료
