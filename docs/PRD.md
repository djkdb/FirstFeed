## 1. 사용자 문제

인스타 입문자는 (P1) 계정 정체성이 넓어 소재가 고갈되고, (P2) 게시물마다 디자인이 달라 일관된 계정으로 보이지 않으며, (P3) 매일 소재를 고르기 어렵다. 게시 뒤에는 (P4) 숫자를 보고도 다음 행동을 정하기 어렵고, 성장하면 (P5) 대외활동·협찬 공지와 마감·필수 표기가 흩어진다. 이번 버전은 P1·P2·P4를 잇는 카드뉴스 기본 흐름을 우선 완성하고, 발굴(P3)은 여유 범위, 운영(P5)은 성과 분석 완료를 조건으로 둔다.

## 2. 제품 목표와 하지 않을 것

| 단계 | 제품 목표 | 달성 기준 |
|---|---|---|

| 2차 | 다른 사람이 실제로 쓸 만한 앱인지 확인한다. | 실사용자 2명이 3주 동안 일주일에 한 번 이상 카드뉴스를 만들어 실제로 게시한다. 격자 일관성은 사용자 설문으로 확인한다. |

이번 버전의 핵심은 브랜드 프로필로 이어지는 기본 흐름을 끝까지 끊김 없이 만드는 것이다. M은 중간 발표까지 필수, F는 최종까지 반드시, S는 여유가 있으면, W는 이번 버전에서 하지 않음이며 W도 삭제하지 않고 향후 계획으로 남긴다. v0.1의 M·F·S에서 W를 새로 분리했고, F와 S는 자료 4의 범위에 맞게 재분류했다. FR-PB-1은 최종 필수 목록에도 있지만 원래 M이므로 M으로 유지한다. 대외활동 FR-OP-1·2·4·5는 조건부 F이며 11월 29일까지 FR-IN-2~6 성과 분석이 끝나지 않으면 W로 옮긴다.

이번 버전에는 인스타 비공식 자동화, AI 이미지 직접 생성, 인스타 외 발행, 결제·구독 판매를 넣지 않는다. 공식 API·이메일 승인·계정 연동이 필요한 예약 발행, 자동 성과 수집, 참고 계정 조회, 이메일 수집과 Supabase 동기화는 W이다. 이전에 만든 개인 자동화 프로그램(카드뉴스공장, insta_auto)의 코드·프롬프트는 대회 규칙에 따라 쓰지 않고 경험과 교훈만 참고한다.

### 차별점
브랜드 프로필 하나가 정체성·브랜딩·고정 템플릿·콘텐츠·성과 갱신의 공통 입력이다. 축의 근거 인용과 콘텐츠의 사실 대조를 코드가 확인하며, 허용 출처는 소재 원문, 브랜드 프로필·키트, 구조에서 나온 숫자, 사용자가 직접 입력한 문장이다. 사용자는 본인 Claude 구독으로 로컬에서 작업하고, 외부 승인이나 자동 발행 없이 업로드 파일을 직접 사용한다. 같은 계정에 관해 처음 정한 방향과 이후 성과에서 배운 내용을 이어 쓸 수 있다는 점에서 개별 디자인·예약 도구와 다르다.

## 3. 타겟 사용자

이번 버전의 주 사용자는 **Claude를 구독하고 있고 인스타를 처음 시작하는 사람**이다. 대표 사용자 ‘민지’는 포트폴리오 겸 계정을 만들고 싶지만 계정 방향과 디자인 틀을 스스로 고르기 어렵다. 실제 시작 후보 1명은 Claude 유료 요금제로 최근 인스타 계정을 만들었으며, 추가로 주변 입문자에게 권할 계획이다(자료 4). v0.1의 도윤(사이드 프로젝트 운영자), 서연(성장 중인 크리에이터)은 확장 사용 시나리오로 남긴다. 서연의 대외활동·협찬 관리는 11월 29일 조건부 범위가 성립할 때만 이번 버전에서 다룬다.

운영 범위는 우선 로컬 1명·브랜드 1개이며 데이터에는 향후 사용자·브랜드 구분 키를 둔다. 여러 사용자 로그인·여러 브랜드 전환 및 다른 기기 사용은 향후 계획이다. CLI가 없는 사용자용 복사형 프롬프트 안내와 API 키 경로는 기본 흐름 완성 뒤 여유 범위다.

## 4. 기능 요구사항

각 행의 ‘수용 기준’은 해당 우선순위 범위에서 관찰·검사할 조건이다. 상태는 자료 3의 2026-10-18 사용자 검토 전 기록으로 끝=끝남, 진=진행, 안=안 함, 신=신규·미구현이다. M/F/S/W는 진행 상태가 아니라 이번 버전의 우선순위다. 조건부 F 네 항목은 11월 29일 점검 전까지 F로 집계한다. 새 번호: FR-AI-6(Codex·Gemini), FR-AI-7(API 키), FR-AI-8(미연결 프롬프트 가이드), FR-MK-9(고정댓글·DM 옵션), FR-AC-6(설치 점검). 향후로 미룬 원래 수용 기준은 W의 향후 기준으로 보존한다.

> **지금 상태는 [`docs/process/status.md`](process/status.md) 가 기준이다**(2026-10-21 추가). 아래 표의 「상태」 칸은 자료 3(2026-10-18) 기록이라 소급해 고치지 않으며, 지금 판정과 다른 칸이 있다(예: FR-ID-1 이 여기는 「끝」, status.md 는 「진행」).

## 5. 핵심 사용자 흐름

1. **정체성 찾기**: 민지가 로컬 앱에서 설문과 AI 인터뷰를 완료하고, 근거가 붙은 브랜드 프로필을 확인·수정·확정한다. 입력이 부족하면 정해진 인터뷰 한도 내에서 더 묻고, 한도가 끝나면 실패를 안내한다. 자료 올리기(F)가 완성되면 PDF·이력서 등을 근거로 추가한다.
2. **브랜딩**: 확정 프로필에서 이름·바이오·팔레트·폰트를 고르고 고정 템플릿을 적용한다. 프로필을 바꾸면 이후 생성에 반영하며 키트 재생성을 안내한다.
3. **카드뉴스·캡션**: 중간 시연에서는 소재 원문을 붙여넣는다. 제목을 고르고 본문·그림 프롬프트·캡션을 생성한 뒤 사실 대조, 렌더링, 소재 밖 풀이 확인을 거친다. 최종 F에서 특정 카드만 말로 고칠 수 있다. 고정댓글·DM 문구는 콘텐츠마다 선택하는 S이며 자동 전송하지 않는다. AI 호출이 실패·취소돼도 미검증 결과를 확정 저장하지 않는다.
4. **업로드**: 업로드 그림만 번호순 폴더에 내보내고 별도 캡션 파일을 이용해 사용자가 직접 인스타에 게시한다. 예약 발행·계정 연결은 없다.
5. **성과 입력**: 인사이트 캡처를 넣고 AI가 읽은 위치와 숫자를 대조한다. 못 읽은 칸은 수정하거나 비운 채 저장하고 ‘입력 안 됨’으로 보인다. 충분히 지난 게시물의 유효한 값만 평균과 다음 행동 제안에 쓴다.
6. **프로필 갱신 제안**: 사용자가 수락하면 변경이 프로필과 제목 생성에 반영되고 ‘성과에서 온 변경’ 이력으로 남는다. 수락한 변경은 3주 뒤 자동으로 빠진다. 발굴 추천 연계는 향후 계획이다.
7. **조건부 운영**: 11월 29일 점검을 통과한 경우에만 활동을 등록하고 공지를 붙여넣거나 캡처해 원문 근거가 붙은 할 일을 확인한 뒤 마감순으로 관리한다. 이메일 수집은 제공하지 않는다.

## 7. 비기능 요구사항·공통 정책

- 보안·개인정보: 로컬 서버는 127.0.0.1에만 바인딩하고 Host·Origin을 검사한다. 사용자 키·토큰은 OS 키체인에 둔다. `.env`는 개발자용이며 사용자 자료·메일 본문은 로컬 처리 대상으로 둔다. 이번 버전에는 메일 연동·동기화를 하지 않는다. CLI는 안전 모드와 빈 임시 폴더에서 권한을 최소화해 실행하며 실행 직전에 구독 여부를 확인한다.
- 실패·취소: JSON 복구 1회와 규칙/렌더링 재작성 총 2회 한도를 따르고, 실패 결과를 확정 데이터로 저장하지 않는다. 사용자가 취소하면 실행 프로세스를 종료하고 cancelled 이력을 남긴다. 오래된 완료 작업 ID는 조용히 정리하되 실제 진행 작업이 사라졌을 때만 안내한다. 취소 뒤 재진입 위치·임시 입력 보존 범위는 미결이다.
- 근거·품질: 공백·문장부호를 정리한 원문 부분 문자열로 인용을 확인한다. 원문 밖 풀이·비유는 원문 용어인 경우만 표시해 사람의 확인/직접 수정 전 업로드를 막는다. 사용자가 직접 고친 문장은 사용자의 입력으로 취급하되 고정 형식·넘침 검사는 유지한다. 원문에 없는 숫자·이름, 읽지 못한 성과 수치를 0으로 만들어 넣지 않는다.
- 렌더링·접근성: Playwright Chromium을 기준 브라우저로 검사하고, 없으면 설치된 Chrome을 사용하되 기준 아님을 표시하며 둘 다 없으면 설치 방법을 안내한다. 자동 내려받기를 약속하지 않는다. PNG마다 사용 브라우저·버전을 기록하고 사용 폰트 로드를 확인한다. 글자/배경 명암비 4.5:1 이상, 격자 3:4 안전 영역은 카드 좌우 34px·릴스 위아래 240px(자료 2의 실제 계정 확인값)로 검사한다. 이미지 대체 텍스트를 제안한다.
- 입력·저장: 그림은 파일 앞부분으로 형식을 판별하고 서버가 이름 지어 앱 데이터 폴더에 저장한다. 업로드 폴더 기본 위치는 `~/Downloads/FirstFeed/`이며 밖에 쓰지 않는다. 프로필 판 생성 사유와 항목 단위 출처(interview/edit/insight/alternative), 항목 만료일을 구분한다. 성과 제안의 3주 자동 제외는 구현 필수이며 현재 만료일 칸만 있는 상태를 완료로 보지 않는다.
- 검증: 같은 입력·고정 판·브라우저 조건에서 동일하게 렌더링한다. v0.1의 카드뉴스 7장 생성/렌더링 5분(렌더링 30초), 원문 밖 숫자 0건, 품질 테스트 세트·재작성 기록은 검증 목표로 유지하되 미측정 성능 달성을 주장하지 않는다. 1회 통과 70%/2회 내 95%, 공지 30건·마감 정확도 90%는 조건부 대외활동 수행 여부에 따라 측정 대상을 명시한다. 외부 서비스의 미확인 글자 제한은 확인 대기로, 해시태그 상한 5는 공식 발표 등급(도움말 원문 미확인)으로 남긴다.

## 11. 아직 정하지 못한 것

- 사용자가 생성 작업을 중간에 그만두고 앱을 다시 열었을 때 어디에서 이어서 시작할지, 미완료 입력·생성 중간 상태를 얼마만큼 보존할지는 미정이다. 취소 즉시 CLI를 끝내고 cancelled 이력을 남긴다는 확정 결정과 구별한다.
- 같은 게시물에 성과 캡처를 두 번 입력했을 때 덮어쓰기·추가 기록·중복 경고 가운데 무엇을 할지, 수정 입력이 평균에 반영되는 시점은 미정이다.
- FR-IN-2에서 모든 수치가 비었거나 도달 값만 비었을 때 저장된 게시물이 분석용 유효 표본에 언제 들어가는지, FR-IN-6의 3주 만료 후 이전 사용자 수정과 어떻게 공존할지는 미정이다. 이미 확정된 ‘빈 수치는 평균·제안 근거에서 제외’와 ‘성과 변경은 3주 뒤 자동 제외’는 유지한다.
- 중간 발표일(11-02 또는 11-04)과 발표·서면 평가 여부의 공식 확정(2026-10-21 받은 공지 — ~~11-03 가정~~), 기능 추가 중단일 12월 7일의 기말고사 일정 반영, 실제 Instagram 앱에서의 글자·이모지 규칙과 해시태그 상한의 도움말 원문, FR-PB-1 ~~실제 업로드 창의 파일 순서 확인~~ 웹 업로드 창의 순서와 FirstFeed 카드로 한 휴대폰 탭 순서 확인이 남아 있다(휴대폰 앱의 흐름은 2026-10-21 확인).
- FR-ID-3에서 깃허브·블로그 주소를 근거로 쓰지만 자동 수집은 하지 않는다(근거: 매니패스트 기능명세서 2.3 「웹 주소를 통한 계정 연동이나 자동 수집은 포함하지 않는다」 · 2장 하지 않을 것의 「인스타 비공식 자동화」와 CLAUDE.md 비목표의 스크래핑 금지). 주소를 받았을 때 사용자가 내용을 붙여 넣게 할지, 공개 페이지를 한 번 읽어 올지는 미정이다.
- 자료 1의 기존 열린 질문인 하이라이트 커버 종류, 기본 틀 배치의 최종 확정 범위, 유료 TTS 후보와 향후 예약 발행 시 토큰 보관 방식, 실사용자 모집 채널은 해당 기능의 착수 범위에 맞춰 결정한다. 현재 확정되지 않은 외부 정책·숫자를 보충해 쓰지 않는다.
