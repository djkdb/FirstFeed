### CLAUDE.md 의 역할

[CLAUDE.md](../../CLAUDE.md) 는 AI 가 **모든 세션 시작 때 끝까지 읽는** 규칙 문서다. 사람의 기억 대신 문서가 맥락을 이어 준다.
- **작업 규칙**(5~7장): 설정값은 한 곳, 프롬프트는 파일로 분리, 모르는 값은 `null`, 지어내지 않기, 확인 못 했으면 「확인 못 함」
- **「이미 내린 결정」**: 결정 + 이유 + 날짜 + 출처. 뒤집을 때는 지우지 않고 줄을 그은 뒤 새 결정을 적는다 → 결정이 어떻게 바뀌었는지가 남는다

- PRD 와 부딪히면 CLAUDE.md 가 우선(CLAUDE.md 머리말) — 개발 중에 바뀐 결정이 PRD 보다 앞서 있기 때문

## 2. 제품 안의 AI 구조

### 어댑터 한 곳

- 모든 AI 호출은 `server/src/ai/adapter.ts` 하나를 거친다. 요청 `{task, prompt, schema, images, web, timeout}` → **스키마로 검증한 JSON**(CLAUDE.md 5장 「AI 호출」)
- 공급자는 `server/src/ai/providers/` — 지금은 Claude Code CLI 하나. 기능 테스트는 모두 가짜 공급자(`server/src/ai/testing/`)로 같은 계약을 쓴다(status.md FR-AI-2)
- CLI 는 `--safe-mode` + 빈 임시 폴더 + `--tools ""` + `--strict-mcp-config` + `--no-session-persistence` 로 실행 — 개발용 CLAUDE.md·사용자 훅이 앱 프롬프트에 섞이지 않게, 파일 쓰기·명령 실행은 절대 열지 않게(결정 2026-10-13 · 뼈대 계획 확인)
- 모델은 과제별 설정(`ai.taskModels`), 동시 호출 수 설정(기본 1), 실행 중 취소 가능(cancelled 로 기록)

### 생성 → 코드 규칙 검사 → 자기 평가 → 재작성

`server/src/ai/loop.ts`

1. **생성** — 프롬프트 파일(`prompts/<이름>/vN.md`) + 스키마
2. **코드 규칙 검사** — 근거 규칙·글자 수·명암비·개수 일치 등. JSON·스키마가 깨지면 다시 요청 1회
3. **자기 평가(AI)** — 다른 프롬프트(`*_review`)로 사실 오류·깨짐을 본다
4. **재작성** — 사유는 두 가지뿐: 코드 규칙 위반, 자기 평가의 「사실 오류」·「깨짐」. 말투·취향 지적은 경고만. 최대 2회(결정 2026-10-13 — CLI 호출이 한 번에 수십 초라 비용이 크고, 성공 지표 「재작성 2회 이내」에 맞춤)
5. 통과 못 한 결과는 **저장하지 않는다**. 재시도 이력은 `ai_runs` 에

- 비용 때문에 자기 평가를 빼는 곳도 정해 두었다: 인터뷰 턴(왕복 대기 시간), 브랜딩 시각 작업(수용 기준이 모두 코드로 잴 수 있음) — 결정 2026-10-13 · 2026-10-14

### 근거 규칙 — 지어내기 방지는 코드로

- 콘텐츠 속 **숫자 · 버전 · 날짜 · 영문 이름**이 허용 출처 4가지(① 소재 원문 ② 브랜드 프로필·키트 ③ 구조에서 나온 숫자 ④ 사용자가 직접 입력한 문장) 어디에도 없으면 재작성(`server/src/rules/grounding.ts`, CLAUDE.md 5장)
- 인용(evidence·quote)은 공백·문장부호를 정리한 뒤 **원문의 부분 문자열인지 코드가 확인**한 것만 저장
- **알려진 한계를 문서에 적어 둔다**(CLAUDE.md 5장 「알려진 한계」) — 숫자는 원문 어딘가에 있는지만 본다, 한글 고유명사는 검사하지 않는다 등. 그 빈틈은 자기 평가가 맡고, 「규칙만 통과했다고 사실이 맞다고 말하지 않는다」

### 용어 풀이 표시

- 입문자용 카드에는 용어 풀이가 필요하지만 맞는지 코드로 잴 수 없다 → **소재 원문에 나온 용어의 풀이만** 허용하고, 그 문장을 표시해 **사람이 확인하기 전에는 업로드 폴더를 만들 수 없다**(결정 2026-10-15 · 2026-10-18, `server/src/cards/gloss-check.ts`)
- 계기: 자기 평가 v2 가 소재 밖 풀이(「태그는 이름표…」)를 못 잡았다(devlog 2026-10-15-04)

### 카드 그림 사람 규칙

- 앱은 그림을 만들지 않고 **그림 프롬프트만** 뽑는다(비목표: AI 이미지 직접 생성)
- 프로필 사진 프롬프트: 실사 인물·신체 금지 — 낯선 사람의 얼굴이 계정 주인처럼 보이므로(결정 2026-10-14). 계기: 측정에서 실제로 실사 인물 프롬프트가 나옴(devlog 2026-10-14-04)
- 카드 그림: 실사 사람 금지 · 그림체 사람 허용 · 나이·외모 특정 금지 · 실존 인물 이름 금지(결정 2026-10-15). 규칙을 바꾸기 전에 지금까지 나온 프롬프트 전체에 돌려 기대값부터 확인(`server/src/brand/visual.ts`, 테스트 `card-people.test.ts`)

### 왜 사용자 구독의 CLI 인가

- 「사용자 본인의 AI 구독으로 돈다」가 핵심 가치(CLAUDE.md 1장) — 운영자가 API 요금을 대지 않고, 사용자도 이미 쓰는 구독으로 쓴다
- 임베딩 같은 API 키가 필요한 방법은 이 원칙과 부딪혀 쓰지 않았다(결정 2026-10-13: 축 유사도는 글자 유사도 + 자기 평가)
- **구독 보호는 경고가 아니라 차단**: 실행 직전 `claude auth status` 로 구독인지 판정하고, 아니면 호출하지 않는다 — 셸에 API 키가 있으면 CLI 가 구독 대신 API 요금으로 도는 것을 실제로 겪었다(CLAUDE.md 「겪은 오류」, devlog 2026-10-13-03)

## 3. 프롬프트 전략

### 버전 관리

- 프롬프트는 코드 안에 쓰지 않고 `prompts/<이름>/vN.md` 파일로 둔다. **기존 파일을 고치지 않고 새 버전을 만든다** → 같은 테스트 세트로 전/후를 나란히 잴 수 있다(결정 2026-10-13)
- 지금 프롬프트 17종 · 버전 파일 28개(`prompts/` 아래, `_system` 제외 — `ls prompts/*/v*.md`)
- 활성 버전은 설정 `prompts.activeVersions` 한 곳(`server/src/config.ts`)

### 평가 스크립트와 테스트 세트

- 평가 스크립트: `eval:identity` · `eval:followup` · `eval:alternatives` · `eval:brand` · `eval:templates` · `eval:cards` · `eval:gloss-review` · `eval:feeling-review`(`package.json`)
- 테스트 세트는 **실제 자료 우선, 부족한 부분만 AI 생성** — AI 가 만든 세트로 AI 를 평가하면 순환이 되어서(결정 2026-10-13). 결과도 **실제·공개 / 실제·비공개(숫자만) / AI 생성**으로 나눈다(CLAUDE.md 6장, `tests/fixtures/real` · `private` · `generated`)
- 측정 결과 파일: `tests/results/` (48개 항목, 2026-10-22 기준 `ls`)
