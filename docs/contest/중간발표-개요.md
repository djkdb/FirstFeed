### 2. 문제 정의 — 직접 겪은 다섯 단계

### 3. 기존 도구와 차이
- Canva·Later·범용 AI·노션은 각 단계 하나씩만 돕고 **단계 사이를 잇지 못한다** — 범용 AI 는 매번 새로 시작하고 기억이 없다
- 퍼스트피드는 **브랜드 프로필 하나**가 정체성·디자인·생성·성과의 공통 입력이고, 숫자·이름은 원문에 없으면 **코드가 되돌린다**
- **근거**: PRD v0.1 「1-3」 비교표(통합본 55~62줄) · PRD v0.2 2장 「차별점」

### 7. AI 워크플로우 — 제품 안
- 모든 호출은 어댑터 한 곳 → 생성 → **코드 규칙 검사** → 자기 평가 → 재작성(최대 2회), 통과 못 하면 저장하지 않는다
- 숫자·날짜·영문 이름은 허용 출처 4가지에 없으면 재작성, 인용은 원문에 실제로 있어야 저장. 소재 밖 풀이는 사람이 확인해야 업로드 폴더를 만든다
- **근거**: AI-활용-계획.md 2장 · `server/src/ai/loop.ts` · `server/src/rules/grounding.ts`
- **캡처**: 구조 그림 한 장(만들 것 — 어댑터 · 루프 · 규칙 · 자기 평가) · 근거 없는 숫자로 재작성된 이력이 보이는 화면(있다면) **(사용자)**

### 8. 프롬프트 전략과 전후 숫자
- 프롬프트는 파일로 나누고 고치지 않고 새 판을 만든다(17종 28판) → 같은 테스트 세트로 전/후를 잰다
- 예: 프로필 v1 → v2 「1회 통과 2/8 → 6/8, 평균 재작성 0.88 → 0.25」 · 바이오의 「하지 않은 약속」 최종 바이오에 남은 수 2 → 0 · 지어낸 감상 「놓침 2/2 → 잡음 2/2」
- 나빠졌는데 채택한 것(자기 평가 v2 — 잡은 4건이 모두 실제 겹침)도 같이 보인다. 표본이 작다는 것도 말한다
- **근거**: AI-활용-계획.md 3장 표(각 숫자의 devlog 줄 · `tests/results/` 파일 · 커밋)
- **캡처**: `tests/results/` 측정 표 한 개(실제·공개 / AI 생성 갈래가 보이는 것)

### 9. 겪은 오류 1 — 측정이 옛 프롬프트로 돌았다
- 새 판으로 잰 줄 알았던 카드 측정이 옛 판으로 돌았다 — zsh 는 따옴표 없는 변수를 단어로 쪼개지 않아 `--prompt` 세 개가 인자 하나로 갔다. 그 결과로 활성 판까지 바꿨었다
- 해결: 인자 읽기를 한 곳으로 모으고 모양이 틀리면 시작 전에 멈춤 → 다시 재니 실제 소재는 오히려 6/0 → 5/1
- **근거**: CLAUDE.md 「겪은 오류」(셸 변수 인자) · devlog 2026-10-18-03 75 · 84줄 · `scripts/prompt-args.ts`
