## ① 프로젝트 기획안 (2쪽 — 독창성 30 · 문제 정의 및 기획 20)

> **한 줄 소개: 게시물 하나 올리기 전에, 30일 뒤 내 계정을 먼저 보여 주는 인스타 시작 도우미**

### 시작 이야기

AI 로 만든 것들을 정리하려고 인스타 계정을 시작해 한 달 만에 팔로워 약 1,500명(8월 28일 기준 1,473명 — 운영자 확인 수치)을 모았고, 대외활동 선정과 협찬 제안으로 이어졌다(PRD v0.1 1-1). 운영하며 얻은 결론은, 누구나 비슷한 결과물을 만드는 시대에는 「나는 누구인가」를 분명히 하는 것이 가장 중요한데 처음 시작하는 사람에게 그게 가장 어렵다는 것이다.

### 문제 정의

인스타 입문자는 (P1) 계정 정체성이 넓어 소재가 금방 떨어지고, (P2) 게시물마다 디자인이 달라 한 계정처럼 보이지 않고, (P3) 매일 소재를 고르기 어렵고, (P4) 숫자를 보고도 다음에 뭘 바꿀지 모르고, (P5) 성장하면 대외활동·협찬 마감이 흩어진다(PRD v0.2 1장). 특히 처음에는 **올려 보기 전까지 내 계정이 어떻게 보일지 알 수 없다.** 이번 버전은 P1·P2·P4 를 잇는 카드뉴스 기본 흐름을 먼저 완성한다.

### 해결 방안 — 퍼스트피드

자기 컴퓨터에서 도는 로컬 앱(웹 화면 + 로컬 서버)이다. 설문과 AI 인터뷰로 **브랜드 프로필**을 만들고, 그 프로필 하나로 이름·바이오·팔레트·폰트 → 고정 템플릿 → **30일 뒤 내 계정 미리보기** → 카드뉴스 → 업로드 폴더까지 이어 간다. AI 는 사용자 본인의 Claude 구독(Claude Code CLI)으로 돈다. 대상은 Claude 를 구독하고 인스타를 처음 시작하는 사람이다(PRD v0.2 3장).

### 대표 차별점 — ⓪ 30일 뒤 내 계정 미리보기 (그림 2 — 근거는 [독창성.md](독창성.md))

정한 아이디·이름·바이오와 프로필 사진, 그리고 첫 9개 게시물이 인스타 프로필 격자에서 어떻게 보일지를 **한 화면에 먼저** 보여 준다. 이미 만든 카드는 실제 표지로, 아직 만들지 않은 칸은 프로필의 축을 돌아가며 AI 가 제안한 「시리즈 계획」 제목으로 채운다. 계획 칸도 고정 템플릿 표지로 그려 보자마자 완성된 계정처럼 보이되 모서리 「계획」 배지로 **만든 카드와 구분**하고, 게시물 수도 「만든 카드 N · 계획 M」으로 나눠 보인다. 격자 칸은 인스타처럼 카드 양옆 34px 를 가린다(운영자가 실제 계정에서 확인한 값). 칸마다 제목을 고치거나 고정할 수 있고, 이미 만든 카드나 다른 칸과 거의 같은 계획 제목은 코드가 다시 쓰게 한다.

**소개 페이지: https://djkdb.github.io/FirstFeed/** (그림 5) — 앱으로 만든 데모 브랜드의 미리보기를 그대로 옮겼다.

### 이 미리보기를 믿을 수 있게 하는 장치

1. **근거 없는 숫자·이름은 코드가 잡아 다시 쓰게 한다** — 계획 제목·카드·캡션의 숫자·영문 이름이 프로필·소재·사용자 글에 없으면 재작성하고, 무엇에 걸려 어떻게 고쳤는지 기록한다. 확인할 수 없는 용어 풀이는 사람이 확인해야 내보낼 수 있다 → **그림 1**
2. **답변 → 정체성 → 브랜딩 → 템플릿 → 카드뉴스가 한 프로필로 이어진다**
3. **프로필을 바꾸면 이후 생성이 바뀐다** — 말투를 반말로, 축 하나를 「실패 기록」으로 바꾸자 바이오가 「…직접 써 본 것만 정리해**요** ⏎ … 📝 **대외활동 기록**」에서 「…직접 써 보고 바로 쓰게 정리**해** ⏎ … 🧯 **실패 기록**」으로 바뀌었다(실제·공개 1회)
4. **정체성의 축마다 사용자가 한 말이 인용으로 붙는다** — 원문에 실제로 있는지 코드가 확인한 인용만 저장한다(측정의 무효 인용 0)

### 기본 흐름의 핵심 기능 (전체는 [PRD v0.2 4장](../PRD.md))

| FR | 기능 | 수용 기준 (한 줄) |
|---|---|---|
| FR-ID-2 | AI 인터뷰 | 한 번에 한 질문씩 3~10개, 근거가 부족한 축이 있으면 한도 안에서 더 묻는다 |
| FR-ID-4 | 브랜드 프로필 초안 | 축 3~5개마다 원문 인용, 인용이 원문에 없으면 버리고 근거 축이 3개 미만이면 인터뷰로 돌아간다 |
| FR-ID-6 | 프로필이 이후 생성의 입력 | 활성 판을 바꾸면 바로 다음 생성의 축·말투·피할 것에 반영된다 |
| FR-BR-6 | 30일 뒤 내 계정 미리보기 | 프로필 화면처럼 한 화면에, 만든 표지 → 계획 칸 → 빈칸 9칸 격자, 만든 칸과 계획 칸 구분, 계획 제목은 근거 대조 · 만든 표지와 거의 같으면 재작성 |

| FR-PB-1 | 업로드 준비 | 올릴 그림만 번호순 폴더에, 캡션 파일은 바깥에, 캐러셀 20장을 넘으면 만들지 않는다 |

범위는 우선순위 M(중간까지) · F(최종까지) · S(여유) · W(이번 버전 안 함)로 나눴다. M 21개 중 끝난 수는 `docs/process/status.md` 집계를 옮긴다(~~2026-10-22 새벽 18개~~ → 2026-10-24 저녁 **18개**, 남은 3개는 사람이 확인해야 하는 것 — PDF 를 만드는 날 다시 본다).

### 개발 파이프라인 (그림 4)

세션마다 **계획(사람 승인) → 구현(AI) → 검증(테스트·화면·PNG 직접 확인) → 기록(devlog)**. 규칙 문서 CLAUDE.md 를 AI 가 세션마다 먼저 읽고, 결정은 날짜·이유와 함께, 오류는 「원인의 모양」으로 쌓는다. 외부 사실(인스타 앱 동작·격자 가림)과 제품 방향은 사람이 정했다(결정 기록 11건 — AI-활용-계획.md 1장). 커밋 전 훅이 개인정보·린트·타입·테스트를 막고, 푸시 뒤 CI 가 다시 본다.

### 제품 안의 AI 구조

모든 호출은 **어댑터 한 곳** → 생성 → **코드 규칙 검사** → 자기 평가(다른 프롬프트) → 재작성(최대 2회) → 통과한 것만 저장. 재작성 사유는 코드 규칙 위반과 자기 평가의 「사실 오류」·「깨짐」뿐이고 말투 지적은 경고만 한다(CLI 한 번이 수십 초라 비용이 커서). CLI 는 안전 모드 + 빈 임시 폴더 + 도구 끔으로 실행해 파일 쓰기·명령 실행을 열지 않는다.

### 환경 설정

Node 24 · TypeScript 6.0.3 · React 19 + Vite 8 · Hono · SQLite(`node:sqlite`) · Playwright Chromium(카드 렌더링 기준 브라우저) · 커밋 전 훅(`.githooks/pre-commit`) · GitHub Actions CI · 프롬프트 파일 `prompts/<이름>/vN.md` · 평가 스크립트 8개 · 대화 기록 내보내기(`npm run export:transcripts`, 키·이메일 등 가림)

## ③ 초기 프롬프트 전략 (1쪽)

- **프롬프트는 코드 밖 파일로, 고치지 않고 새 판을 만든다** — 같은 테스트 세트로 전/후를 나란히 잰다. 지금 17종 31판(`prompts/`, 개발용 시험 프롬프트 1종 제외)
- **테스트 세트는 실제 자료 우선**, 부족한 부분만 AI 생성. 결과도 실제·공개 / 실제·비공개 / AI 생성으로 나눈다(AI 가 만든 세트로 AI 를 평가하면 순환이라서)
- **전후 숫자** (각 숫자의 파일·커밋은 AI-활용-계획.md 3장)

| 바꾼 프롬프트 | 전 → 후 | 단서 |
|---|---|---|
| 정체성 프로필 v1 → v2 | 1회 통과 2/8 → 6/8, 평균 재작성 0.88 → 0.25 | 짧은 인용 문제는 프롬프트가 아니라 코드 수정으로 풀렸다 |
