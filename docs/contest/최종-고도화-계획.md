# 최종 심사까지 고도화 계획 — 내 입장에서

> 2026-11-22 만듦. 최종 발표는 12월 말. 이 문서는 **심사 항목마다 「심사위원이 무엇을 보고 점수를 주는가」 → 「나는 지금 무엇을 보여 줄 수 있나」 → 「무엇이 비었나」 → 「다음에 할 일」** 순으로 적고, 일을 끝낼 때마다 고친다.
> 쓰는 입장: **나(운영자)** 가 주어다. 나는 AI(Claude Code)에게 일을 시키고, 결과를 직접 확인하고, 틀린 것을 잡아 다시 시켰다. 코드 대부분은 AI 가 썼다 — 그것을 숨기지 않고, 대신 **내가 무엇을 요구했고 어떻게 검증했고 어디서 AI 를 멈춰 세웠는지**를 보여 준다. 숫자는 레포에서 잰 · 센 값만 쓴다.

## 점수표 (비중 × 지금 빈 정도로 순서를 정한다)

| 항목 | 비중 | 심사위원이 보는 것(공지 문장) | 내가 지금 보여 줄 수 있는 것 | 비어 있는 것 | 우선 |
|---|---:|---|---|---|---|
| 프롬프팅 및 트러블슈팅 | **40%** | 의도한 결과를 얻기 위해 프롬프트를 어떻게 개선했으며 발생한 오류를 논리적으로 디버깅했는가 | 프롬프트 23종 41판(전/후 파일이 나란히) · 측정 결과 `tests/results/` 87개 · 「겪은 오류」 27개(원인의 모양 → 해결 → 재발 방지) | 흩어져 있다 — 한 번에 읽히는 **사례집**이 없다. 사례마다 「내가 무엇을 보고 이상하다고 느꼈나」가 빠져 있다 | **1** |
| 결과물 완성도 | 30% | AI를 활용하여 기획한 핵심 기능이 작동하는 프로토타입을 성공적으로 구현했는가 | 정체성 → 브랜딩 → 템플릿 → 카드뉴스 → 업로드 폴더 → 30일 미리보기 · 「오늘 올릴 것」 · 채팅 고치기 · 릴스 편집 · 설정 탭이 실제로 돈다(M 21 중 끝남 18) | **고리가 안 닫혔다** — 1장 「무엇」의 성과 분석(FR-IN-2~6, F)이 코드 0. 「올린 뒤 → 성과 → 프로필이 바뀐다」가 없어서 「프로필 하나가 모든 단계를 잇는다」를 끝까지 보여 줄 수 없다. 릴스 대본(FR-MK-4) 없음. 11-29 까지 IN 이 안 끝나면 대외활동이 W 로 간다 | **2** |
| 경험과 성장 | 20% | 바이브코딩을 통한 개발 과정에서의 기술적 배움이 명확한가 | devlog 46편 · 결정 이력(줄 그은 것 포함) | 「배운 것」이 내 말로 정리된 곳이 없다(회고는 빈칸) | 3 |
| 발표 및 시연 | 10% | 작업 과정과 AI와의 협업 내역을 청중에게 명확하고 설득력 있게 전달했는가 | 소개 페이지 · 리허설 1회 기록 | 발표 형식 공지 대기 · 시연 영상 · 슬라이드 뼈대 · 클라우드 세션 대화 기록 꺼내는 법 | 4 |

## 할 일 (순서대로 — 끝내면 줄을 긋고 날짜)

### 1. 프롬프팅 · 트러블슈팅 사례집 (40%)
- [ ] `docs/contest/프롬프트-개선-사례.md` — 5개를 고른다. 사례마다: **내가 본 이상한 결과**(실제 출력 발췌) → **내가 세운 가설** → **바꾼 프롬프트 전/후 발췌**(파일 판 번호) → **같은 입력으로 다시 잰 숫자** → **안 된 것 · 코드로 넘긴 것**. 후보: 프로필 v1→v2(인용 규칙, 프롬프트가 아니라 코드가 효과를 낸 사례) · 바이오 「하지 않은 약속」 · card_body v3(측정이 틀렸다가 정정) · 계획 v3→v4(같은 소재 반복) · 꼬리질문 v4→v5(「이 사람」 → 직접 말하기) · 앱 전용 시스템 프롬프트(토큰 −35%)
- [ ] `docs/contest/트러블슈팅-사례.md` — 5개. 사례마다: **증상(그대로)** → **처음 의심한 것과 그게 틀린 이유** → **확인한 방법(명령 · 실험)** → **원인** → **고친 것** → **다시 안 겪게 한 장치(테스트 · 훅 · 규칙)**. 후보: 잠자기로 늘어난 시간(hrtime 가설이 틀림 → SIGSTOP 실험) · 부모 환경이 과금 경로를 바꿈 · 측정이 옛 판으로 돈 것(zsh 인자) · 목록 번호를 사실 숫자로 셈 · 스트림 끊김으로 서버가 죽음 · `auth status` 가 가짜 토큰도 통과
- [ ] 앞으로 만드는 기능(성과 분석 제안 FR-IN-5)에서 **프롬프트 전/후를 처음부터 재도록** 설계한다 — 사례가 하나 더 생긴다

### 2. 고리 닫기 — 성과 분석 FR-IN-2~6 (30%, 11-29 기한)
- [ ] 계획을 보여 주고 확인받은 뒤 만든다(CLAUDE.md 7장). PRD 수용 기준 그대로: 인사이트 캡처에서 숫자 읽기 + 원본 위치 나란히 · 못 읽은 값은 빈칸(0 아님) · 게시 48시간 뒤부터 · 축 · 형식 · 제목 유형별 저장률 · 공유율(표본 3개 미만은 결론 없음) · 제안 최대 3개(표에 없는 숫자를 쓰면 재작성) · 수락해야 프로필 갱신 · 3주 뒤 자동으로 빠짐 · 이력에 「성과에서 온 변경」
- [ ] 이미 있는 것: 프로필 항목마다 출처 `insight` · 만료일 칸(결정 2026-10-14 — 자동으로 빼는 로직만 없음)
- [ ] 시연 흐름: 「오늘 올릴 것」에서 「올렸어요」 → 48시간 뒤 인사이트 캡처 올리기 → 표 → 제안 수락 → 다음 계획 제목이 바뀐다

### 3. 그다음 완성도
- [ ] 릴스 대본(FR-MK-4) → 대본에서 편집 화면까지 한 번에
- [ ] 티스토리 · 리틀리 · 폰으로 받기를 **내 계정 · 내 휴대폰으로** 한 번씩 끝까지(사람만 할 수 있음)

### 4. 경험과 성장 (20%)
- [ ] `docs/contest/배운-것.md` 초안 — devlog 에서 「처음엔 이렇게 생각했는데 틀렸다」 순간을 뽑아 **내가 고쳐 쓸 초안**으로. 마지막 문장은 내가 쓴다

### 5. 발표 · 시연 (10%)
- [ ] 슬라이드 뼈대(양식 5개 순서) · 시연 대본(실시간 / 미리 만든 결과 표시) · 영상 대비
- [ ] 클라우드 세션 대화 기록 꺼내는 법 확인

## 지킬 것
- 「AI 가 다 했다」도 「내가 다 짰다」도 아니다 — **시킨 것 · 확인한 것 · 멈춰 세운 것**이 내 몫이다
- 숫자는 다시 셀 수 있는 것만(셈법을 옆에 적는다). 한 번 · 한 사람 측정은 그렇다고 적는다
- 미리 만든 결과는 시연에서도 「미리 만든 결과」로 보인다(결정 2026-10-18)
