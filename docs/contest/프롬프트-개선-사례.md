# 프롬프트 개선 사례 5+1

> 2026-11-28 초안. 최종 심사 「프롬프팅 및 트러블슈팅」(40%)용 — [최종-고도화-계획.md](최종-고도화-계획.md) 1번 할 일.
> 사례마다 **이상한 결과 → 가설 → 바꾼 것(전/후) → 같은 입력으로 다시 잰 숫자 → 안 된 것 · 코드로 넘긴 것** 순서다. 숫자와 인용은 모두 링크한 devlog · 측정 결과에 있는 것만 옮겼다.
> **「내가 본 것」 칸은 운영자가 직접 쓴다** — 그 순간 무엇을 보고 이상하다고 느꼈는지는 기록에 없어서 지어내지 않고 비워 두었다.
> 측정 갈래: **실제·공개**(운영자 본인 자료) · **AI 생성**(가상 인물). 실제·비공개 자료로 잰 사례는 없다. 표본이 작다(사람당 1~2회) — 숫자는 「이 조건에서 이렇게 나왔다」로만 읽는다.

## 1. 정체성 프로필 v1 → v2 — 효과를 낸 것은 코드였다

- **이상한 결과**: 10-13 화면 흐름에서 프로필이 `quote_too_short`(「만든 것」·「대학생」)로 두 번 재작성됐다
- **내가 본 것** (직접 쓰기):
- **가설 → 확인**: 프롬프트에는 설문 답이 `[S4] 보여줄 수 있는 것: 만든 것` 으로 보이는데, 코드가 대조하는 원문은 `만든 것` 뿐이었다. 보이는 줄 그대로 옮기면 `quote_not_in_source`, 답만 옮기면 짧아서 `quote_too_short` — **빠져나갈 수 없는 구조**였다
- **바꾼 것**
  - 코드: 대조 원문을 규칙 문서대로 「라벨: 답」 한 줄로. 라벨만 옮긴 인용은 따로 막음(`label_only_quote`)
  - 프롬프트 v2: 설문은 한 줄 전체 인용 · 검토자 시점 3인칭 금지 · 선택지는 보조 근거로만 · 겹침 기준을 자기 평가와 같은 말로
- **다시 잰 숫자** (같은 코드에서 v1/v2, 8회씩 — 실제·공개 1명 × 2 + AI 생성 3명 × 2)

  | 지표 | v1 | v2 |
  |---|---:|---:|
  | 1회에 통과 | 2/8 | **6/8** |
  | 평균 재작성 | 0.88 | **0.25** |
  | 평균 시간 | 81초 | 63초 |
  | 근거 축 3개 미만 | 4/8 | 4/8 (그대로) |

- **안 된 것 · 읽은 것**: `quote_too_short` 는 v1 · v2 모두 0 — **짧은 인용 재작성을 없앤 건 프롬프트 v2 가 아니라 코드 수정**이었다. v2 의 몫은 인용이 한 줄 전체로 바뀐 것(0/11 → 10/10). 3인칭 금지는 이 세트에서 v1 도 0이라 효과를 말할 수 없다
- **남긴 장치**: 테스트는 코드의 지금 값이 아니라 **규칙 문서의 문장**을 검사한다(「겪은 오류」)

## 2. 꼬리질문 v4 → v5 — 프롬프트의 말버릇이 화면으로 샜다

- **이상한 결과**: 사용자 시뮬레이션(11-09)에서 인터뷰의 「왜 묻나요?」가 「이 사람이 직접 겪은 한 장면을 모아야…」 — 화면을 읽는 사용자를 3인칭으로 불렀다
- **내가 본 것** (직접 쓰기):
- **가설**: 프롬프트가 사용자를 줄곧 「이 사람」이라고 부르니, AI 가 그 말을 사용자에게 보일 문장에도 그대로 썼다
- **바꾼 것**: v5 — why 는 사용자에게 직접 하는 말로(「~하려고 물어요」), 「이 글에서 이 사람은 설명용일 뿐」이라고 밝힘 + 코드 규칙 `why_third_person`(「이 사람 · 이분 · 사용자 · 계정 주인」이 나오면 재작성)
- **다시 잰 숫자** (가상 응답자 4명 × 6질문, AI 생성)

  | 판 | 재작성 | 사유 |
  |---|---:|---|
  | v4 | 6번 | `why_third_person` 5 · `multiple_questions` 1 |
  | v5 | **0번** | — |

- **안 된 것 · 읽은 것**: v4 를 처음 쟀을 때는 시뮬레이션이 재작성 **사유**를 남기지 않아 「4번 다시 썼다」만 알 수 있었다 → 사유를 남기게 고치고 v4 를 다시 쟀다. 각도 다양성은 v4 5·5·5·5 / v5 6·6·5·6 으로 떨어지지 않았다
- 출처: [devlog 2026-11-09-01](../devlog/2026-11-09-01-사용자-시뮬레이션.md) · `tests/results/2026-11-09-interview-sim-why-v4.md` · `-v5.md`

## 3. 성과 제안 v1 → v2 — opus 에게 문장 수를 세게 하고 있었다

- **이상한 결과**: 제안 프롬프트를 처음 실제 AI(opus)로 3번 돌리니 2번이 자기 평가 「깨짐」 → 재작성. 사유는 둘 다 「제안이 한 문장이 아니라 두 문장」(「릴스를 더 올린다. 공유율이 0.6%로 … 높았다.」)
- **내가 본 것** (직접 쓰기):
- **판단**: 문장 수는 **코드로 잴 수 있는 것**인데 opus 자기 평가 + 재작성(호출 2번, 약 15초)을 쓰고 있었다
- **바꾼 것**
  - 코드 규칙 `text_not_one_sentence` 로 내림. 배수 비교(「2배」)와 「11%」=「11.0%」도 코드로
  - 전(v1): 「text: 한 문장, {{max_chars}}자 이내. 무엇을 더(덜) 할지와 표에서 본 근거 값」
  - 후(v2): 「text: **마침표가 끝에 하나뿐인 한 문장**」 + 좋은 예(「저장률 6.6%로 릴스 3.9%보다 높았던 캐러셀을 더 올린다.」) · 나쁜 예(두 문장 · 덧붙인 조각) + 「배수 비교는 표에 없는 계산이라 쓰지 않는다」
- **다시 잰 숫자**

  | 입력 | 판 | 횟수 | 재작성 |
  |---|---|---:|---:|
  | AI 생성(합성 표) | v1 | 2 | 1 |
  | AI 생성(합성 표) | v2 | 3 | **0** |
  | 실제·공개(운영자 계정 숫자 — 레포에 저장 안 함) | v1 | 1 | 1 |
  | 실제·공개(같은 숫자) | v2 | 1 | **0** |

- **사람이 읽은 판정**: v2 제안 12개 모두 표의 비율 글을 그대로 썼고, 원인을 지어낸 문장(「사람들이 ~를 좋아해서」)은 없었다

## 4. 앱 전용 시스템 프롬프트 — 매번 붙는 몫부터 쟀다

- **이상한 결과**: 토큰을 줄이려고 재 보니, 아주 짧은 프롬프트 + 작은 스키마만 보내도 입력이 sonnet 3,288 · opus 3,358 토큰. 한 번의 흐름(호출 18.5번)에서 입력 139k 의 약 44% 가 이 고정 몫이었다
- **내가 본 것** (직접 쓰기):
- **가설**: 고정 몫은 CLI 의 기본 시스템 프롬프트 · 설정 · 슬래시 명령이다 — 과제 프롬프트를 깎기 전에 이것부터
- **바꾼 것**: CLI 호출에 앱 전용 시스템 프롬프트 · `--setting-sources ""` · `--disable-slash-commands`. 설정 `ai.appSystemPrompt` 로 끄면 전/후 비교 가능. `--help` 로 옵션 범위를 확인했다(`--exclude-dynamic-system-prompt-sections` 는 기본 시스템 프롬프트에만 적용이라 안 씀)
- **다시 잰 숫자**

  | 호출 | 전 | 후 | 차이 |
  |---|---:|---:|---:|
  | 고정 토큰 sonnet / opus | 3,288 / 3,358 | 2,166 / 2,160 | −34% / −36% |
  | 꼬리질문 생성 (sonnet) | 7,812 | 4,078 | −48% |
  | 카드 본문 생성 / 재작성 | 7,194 / 9,853 | 5,991 / 7,836 | −17% / −20% |
  | 자기 평가 ← 카드 본문 | 10,405 | 8,483 | −18% |

- **안 한 것 · 이유**: 2단계(과제 프롬프트 새 판으로 공통 규칙 빼기)는 만들지 않았다. 되풀이되는 규칙이 과제마다 1~3줄이라 줄어들 몫(호출 1번에 수백 토큰)보다 새 판마다 전/후 측정하는 비용이 크다고 봤다 — 「사용자 확인 필요」로 남김
- **확인한 것**: 이미지 경로(Read 만) · 웹 경로(WebSearch · WebFetch 만) · 일반 경로 모두 구조화 출력 정상

## 5. 꼬리질문 v5 → v6 — 프로필이 왜 돌아왔는지 다음 질문이 몰랐다

- **이상한 결과**: AI 가상 사용자 테스트(11-28 A0)에서 「프로필 만들기」가 「근거 있는 축이 3개가 되지 않았습니다」로 두 번 돌아오며 2분 22초를 기다렸다. 화면에 「부족한 것」(셋째 축 · 피할 것)이 보였는데 다음 질문은 「남이 보는 나」 — 이어지지 않았다
- **내가 본 것** (직접 쓰기):
- **가설 → 확인**: v5 는 돌아온 이유를 **받지 못한다**(`runFollowup` 에 그 값이 없음). 그리고 돌아온 직후에도 버튼이 그대로 보여 같은 답으로 다시 부를 수 있었다
- **바꾼 것**
  - 프롬프트 v6: 「프로필 만들기에서 돌아온 이유」 칸(`{{profile_gap}}`) — 부족한 것이 있으면 이번 질문은 그중 하나를 채우는 질문으로, 채워지기 전에는 `ready_for_profile` 을 true 로 하지 않는다
  - 코드: 돌아온 뒤 새 답이 `identity.retryMinNewAnswers`(2)개 쌓이기 전에는 ready 를 무시하고, ready 전에는 서버가 프로필 만들기를 거절(AI 호출 없음) · 화면도 같은 조건으로 단추를 숨김. 질문을 다 쓰면(10개) 막지 않는다
- **다시 잰 숫자**: 2026-11-28 측정 중 — `npm run eval:interview -- --turns=4 --until-profile --versions=v5:v3,v6:v3` (가상 응답자 4명, AI 생성)
