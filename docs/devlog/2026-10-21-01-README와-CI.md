## 결정 · 판단 (이번 세션)

`#결정`
- **개인정보 검사의 1차 방어선은 커밋 전 훅이고, CI 는 푸시 뒤 검출용이다** — 훅(`--staged`)은 커밋에 들어가기 전에 막는다. CI 는 이미 공개 레포에 올라간 뒤에 알리는 것이라 **막지는 못한다**(올라간 값은 지워도 기록·캐시에 남을 수 있다). CI 가 잡는 것은 훅을 건너뛴 커밋(`--no-verify`)·훅이 켜지지 않은 다른 컴퓨터의 커밋·허용 목록 변경으로 생긴 놓침이다. CI 는 플래그 없이 전체 파일을 다시 본다
- **CI 는 ubuntu-latest**(사용자 결정) — 앱은 macOS 우선이지만 단위 테스트는 운영체제와 상관없어야 하고, Windows 확인 전에 이식성 문제를 먼저 드러낸다. 첫 실행에서 리눅스 때문에 깨진 테스트는 없었다
- 브라우저 테스트(`*.browser.test.ts` 56개)는 CI 에 넣지 않음(아래 제안)

## 브라우저 테스트를 CI 에 넣으려면 (제안만)

1. 브라우저: `npx playwright install --with-deps chromium`(리눅스는 시스템 라이브러리까지, 내려받기 수백 MB · 시간이 늘어남). 캐시를 쓰려면 `~/.cache/ms-playwright` 를 Playwright 판 기준으로 캐시
2. 폰트: 렌더링 테스트는 폰트를 실제로 불러와야 PNG 를 만든다(결정 2026-10-15). npm 폰트 패키지는 `npm ci` 로 오지만, 레포에 넣은 폰트(페이퍼로지 등)와 시스템 대체 글꼴이 리눅스에서 같은지 확인 필요
3. 기준 브라우저: 넘침 판정의 기준은 Playwright Chromium 하나라 macOS 와 리눅스에서 같은 판이면 같아야 하지만, 글꼴 힌팅·안티에일리어싱 차이로 경계값 테스트가 흔들릴 수 있다 — 처음엔 `continue-on-error` 로 몇 번 돌려 차이를 잰 뒤 필수로
4. 시간: 로컬에서 브라우저 묶음은 파일 병렬을 끄고 차례로 돈다(겪은 오류 2026-10-15). CI 에서는 단위와 다른 job 으로 나눠 단위 결과가 먼저 나오게
5. 개인정보: 브라우저 테스트가 만드는 PNG 는 CI 산출물로 올리지 않는다(올리면 공개)
