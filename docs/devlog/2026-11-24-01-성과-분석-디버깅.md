## 오류 → 원인 → 해결

- `#트러블슈팅` **바깥 데이터의 모양을 실제 표본 없이 짐작하고, 테스트가 그 짐작을 굳혔다**
  - 증상: 겉으로는 아무 오류도 없었다. 그런데 앱이 모든 게시물 시각을 9시간 앞당겨 읽고 있었다 → 「게시 48시간 뒤부터」 판정과 「올렸어요 ±3일」 잇기 범위가 틀어짐
  - 의심 1(틀림): 시간 범위로 잘라 보면 알 수 있다 → 9:10~9:40 과 18:10~18:40(KST) 두 창 모두 같은 게시물이 나왔다. **Metricool 의 from/to 는 날짜(일) 단위로만 거른다**는 것을 대신 알게 됨
  - 확인: 인스타 게시물 ID 앞부분에는 만든 시각이 들어 있다(`(id >> 23) + 1314220021721` ms). 피드 3개는 Metricool 시각을 **UTC 로 읽었을 때 초까지 같았고**, 릴스 7개는 몇 초~6분 늦었을 뿐(올림 → 게시) — KST 로 읽으면 늘 9시간이 어긋난다
  - 원인: 11-22 구현은 「브랜드 시간대가 Asia/Seoul 이니 시각도 그 시간대겠지」라고 짐작했고, 테스트도 `parseStamp('20261118092331','Asia/Seoul') → 00:23:31Z` 로 그 짐작을 정답처럼 적어 두었다
  - 해결: UTC 로 읽고(`parseStamp`), 테스트를 실제 응답 모양(그 게시물 ID 의 시각 · JSON null · "0")으로 다시 씀
  - 다시 안 겪으려면: 바깥 서비스의 값은 **실제 응답 한 번을 받아 그 모양으로 테스트를 쓴다**. 시각은 다른 출처(여기서는 게시물 ID)와 맞춰 본다
  - CLAUDE.md 「겪은 오류」에 올림: 예
- 코드 검토로 고친 것(심각도 순): 없어진 브랜드가 저장돼 있으면 불러오기가 계속 실패하고 화면에서 고칠 길이 없음 · 빈 제안 실행 뒤에도 옛 제안이 「프로필에 반영」 가능(→ 제안 묶음, 마이그레이션 023 · 실패 · 결론 없음 실행도 옛 제안을 거둠) · 「3배」 「세 배」 · 전각 숫자가 근거 대조를 빠져나감 · 「다시 연결」이 로그인 전에 성공으로 보임 · MCP 협상 판을 안 씀 · 세션 404 에 다시 시작 안 함 · 「놀러 가요」 같은 평서문을 질문형으로 셈 · 새로 받은 토큰을 잃는 두 경우 · 메타데이터 주소를 손으로 만듦
