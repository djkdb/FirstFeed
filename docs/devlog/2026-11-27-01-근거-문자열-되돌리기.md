## 결정과 이유
- `#결정` **004 는 건드리지 않는다.** 이미 적용된 마이그레이션은 체크섬 검사에 걸려 서버가 시작을 멈춘다(겪은 오류 「이미 적용된 마이그레이션 파일을 고치면…」). 새 DB 는 004 → 024 순서로 지나가며 바로잡히고, 쓰던 DB 는 024 만 새로 적용된다
- `#결정` **이미 배열인 판은 UPDATE 대상에서 뺀다**(`WHERE EXISTS … json_type = 'text'`). 멀쩡한 자료를 다시 쓰지 않으려고

## 오류 → 원인 → 해결
| 구분 | 내용 |
|---|---|
| 오류(사람의 실수) | 변환 SQL 을 쓸 때 「하위 질의가 돌려준 JSON 은 문자열로 취급된다」는 SQLite 동작을 놓침 |
| 결함 | 004 의 `json_set(…, '$.evidence', (SELECT json_group_array(…)))` |
| 고장 | 옛 형식 프로필의 근거 목록이 배열이 아니라 문자열로 저장됨 |
| 영향 | 2026-10-14 이전 형식의 프로필을 가진 DB 만. 그 뒤에 만든 프로필은 앱 코드가 배열로 저장하므로 해당 없음 |
| 해결 | 024 로 되돌림. 단위 테스트 519개 전부 통과 · 린트 · 타입 체크 통과 (Node 24.22.3 · SQLite 3.54.1) |
