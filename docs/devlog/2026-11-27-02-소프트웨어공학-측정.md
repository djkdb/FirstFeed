## 오류 → 원인 → 해결

- `#트러블슈팅` **얕은 복제(shallow clone)에서 git 기록으로 재면 아무 오류 없이 일부만 센다**
  - 증상: `git log` 커밋 260개, 첫 커밋이 2026-10-15 13:11 — 10-18 측정의 첫 커밋(10-13 21:26 · 168개까지)보다 늦었다. 그대로 쟀다면 10월 세션 앞부분이 통째로 빠진 표가 나왔다
  - 원인: 클라우드 컨테이너는 레포를 얕게 받는다(`git rev-parse --is-shallow-repository` → true). git 은 잘린 기록을 그대로 보여 줄 뿐 경고하지 않는다
  - 확인: 10-18 문서의 「다시 재는 법」 0) 첫 커밋 `0e3b741` 과 대조. `git fetch --unshallow` 뒤 399개 · `git log 6069973 | wc -l` = 168(10-18 과 같음)
  - 해결: 기록을 다 받은 뒤 다시 잼. metrics.md 「다시 재는 법」 첫 줄에 `git fetch --unshallow`
  - 다시 안 겪으려면: git 기록으로 재기 전에 얕은 복제인지 보고, **지난번 측정의 기준 숫자(첫 커밋 · 커밋 수)를 다시 낼 수 있는지 먼저 확인**한다
