# 개발 기록 (devlog)

최종 발표의 「프롬프트 엔지니어링 과정 · 트러블슈팅」(최종 심사 40%)과 「경험과 성장」(20%) 자료가 여기서 나온다.
**나중에 기억으로 재구성하지 않도록, 세션이 끝나기 전에 그날 쓴다.**

## 언제 · 어떻게 쓰나
- **세션 하나 = 파일 하나.** 같은 날 세션이 여러 개면 번호를 올린다
- 파일 이름: `YYYY-MM-DD-NN-짧은-주제.md` (예: `2026-10-13-01-PRD-질의응답과-규칙-문서.md`)
- [_template.md](_template.md) 를 복사해서 채운다. 해당 없는 칸은 지우지 말고 "없음"이라고 적는다 (빈칸인지 잊은 건지 구분하려고)
- 다 쓰면 아래 「목록」 표에 한 줄을 더한다
- 오래 유지될 결정은 [CLAUDE.md](../../CLAUDE.md) 「이미 내린 결정」에, 다시 겪을 수 있는 오류는 「겪은 오류」에도 올린다

## 무엇을 남기나 — 발표 자료가 되는 것만
| 칸 | 왜 남기나 | 발표에서 쓰이는 곳 |
|---|---|---|
| 한 일 | 일정 대비 진척 | 결과물 완성도 · 회고 |
| 결정 + 이유 + 버린 대안 | "왜 이렇게 만들었나"에 답하려고 | AI 활용 계획 · 기획 |
| 오류 → 원인 → 해결 | 증상만 적으면 다음에 못 알아본다. **원인의 모양**을 적는다 | 트러블슈팅 |
| 프롬프트 변경 전/후 | 무엇을 왜 바꿨고 **숫자가 어떻게 변했나** | 프롬프트 엔지니어링 과정 |
| AI 협업 메모 | AI가 틀렸던 것, 사람이 바로잡은 것, 잘 먹힌 지시 방식 | AI 활용 · 경험과 성장 |
| 세션 ID | 대화 원본을 찾아 제출용으로 꺼내려고 | AI 대화 기록 제출 |

## 태그 — 발표 자료를 모을 때 검색용
본문 항목 앞에 붙인다. `grep -rn "#트러블슈팅" docs/devlog` 로 모은다.

| 태그 | 붙이는 곳 |
|---|---|
| `#결정` | 설계·범위 결정 |
| `#트러블슈팅` | 오류 → 원인 → 해결 |
| `#프롬프트` | 프롬프트 변경 전/후 |
| `#측정` | 테스트 세트로 잰 숫자 (통과율·재작성 횟수·원문 밖 숫자·임계치) |
| `#AI협업` | AI가 틀린 것·사람이 고친 것·지시 방식에서 배운 것 |

## 세션 ID 찾는 법
Claude Code 대화는 `~/.claude/projects/-Users-lee-Claude-FirstFeed/<세션ID>.jsonl` 에 저장된다. 가장 최근 수정된 파일이 지금 세션이다.
```bash
ls -t ~/.claude/projects/-Users-lee-Claude-FirstFeed/*.jsonl | head -1
```
대화 원본은 레포에 넣지 않는다. 제출용은 `npm run export:transcripts -- <세션ID>`(또는 `--latest`)로 `exports/` 에 꺼내며, 그때 키·토큰·이메일·전화번호를 가린다.
