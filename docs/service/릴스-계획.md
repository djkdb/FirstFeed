### ffmpeg (실험 b)
- 이 맥: `/opt/homebrew/bin/ffmpeg` · `ffprobe` **8.1.2**(Homebrew, `brew info`: 안정판 9.0.2 있음). 인코더 `libx264` · `h264_videotoolbox` · `aac` 있음
- 라이선스: 이 빌드는 `--enable-gpl --enable-libx264 --enable-version3`(GPL 빌드). **앱은 ffmpeg 를 같이 넣지 않고 사용자 컴퓨터에 깔린 것을 별도 프로그램으로 부른다** — 배포하지 않으므로 GPL 조건이 앱 코드에 걸리지 않는 방식(법률 판단 아님 — 「확인 필요」 표시로 남김). 앱이 만든 mp4 자체는 라이선스 문제 없음(코덱 특허는 확인 못 함)
- 설치 안내(doctor 문구 후보): macOS `brew install ffmpeg`, Windows 는 공식 사이트(ffmpeg.org) 의 빌드 안내 — Windows 경로는 실제로 깔아 보지 않음(확인 못 함)

## 3. 경로별 결과물

| 경로 | 만드는 것 | 업로드 폴더에 들어가는 것 | AI · 외부 호출 |
|---|---|---|---|
| 미노출 | 대본 → 문장별 TTS → 길이로 타임라인 → 브랜드 모션(글자 장면 + 자막) → mp4 | `업로드/01_reel.mp4` · 릴스 표지 PNG · `캡션.txt` · `대본.txt` · `자막.srt`(TTS 길이로 정확) | 대본 AI 1~2(+자기 평가) · TTS 문장 수만큼 |
| 캐릭터 | 미노출과 같고, 모션에 **사용자가 올린 캐릭터 그림**(브랜드 「그림 올리기」와 같은 함수). 생김새를 지어내지 않는 규칙 그대로 — 그림이 없으면 글자 모션만 | 미노출과 같음 | 미노출과 같음 |
| 노출 | **직접 찍기 도우미** — TTS · 모션 없음. 대본(같은 근거 규칙) · 컷 목록(장면마다 무엇을 찍을지 · 몇 초) · 화면에 넣을 글자(9:16 가림 안) · 자막 | `찍기-대본.txt` · `컷-목록.txt` · `화면-글자.txt` · `자막.srt`(**문장별 시간은 대본 길이로 추정했다고 파일 머리에 표시**) · 릴스 표지 PNG · `캡션.txt` | 대본 AI 1~2(+자기 평가) |

- 모든 경로: 대본은 근거 규칙(숫자 · 영문 · 목록 번호 규칙 포함) · 풀이 표시 규칙 · 「지어낸 감상 = fact」 그대로, 표시된 풀이는 확인 전엔 폴더를 만들지 않는다(결정 2026-10-18)
- 노출 경로의 「추정 길이」 = 글자 수 ÷ 초당 글자 수. 초당 글자 수는 실험 a 의 TTS 길이로 처음 값을 정하고 설정에 둔다(감으로 정하지 않음)

## 4. 흐름 (미노출 · 캐릭터)

1. **입력**: 소재(또는 만든 카드 세트) — 카드 만들기와 같은 소재 · 프로필 · 고정 템플릿
2. **대본** `prompts/reel_script/v1.md`(새 판, 이전 프로그램 프롬프트 안 씀): 문장 단위 `[{text, on_screen?, gloss?}]` + 훅 + 표지 문구. 규칙(코드): 근거 대조 · 풀이 표시가 글에 있는지 · 문장 수 · **추정 길이 15~30초**(초당 글자 수 설정) · 화면 글자 길이(고정 틀 칸 예산). 자기 평가는 카드와 같은 기준(fact · broken 만 재작성)
3. **TTS**: 문장마다 한 번(문서상 시간 정보가 없어서). 같은 글 · 목소리 · 속도면 다시 부르지 않는다(캐시). 무료 판 동의가 없거나 키가 없으면 건너뛰고 무음
4. **타임라인**: 문장 길이(ffprobe) + 문장 사이 쉼(설정) → 장면 시작 · 끝. 무음이면 추정 길이
5. **모션**: 브랜드 템플릿의 9:16 장면(HTML/CSS 애니메이션) — 축 색 변형(`pillarCoverLook`) · 명암비 4.5:1 규칙 재사용, 제목 · 자막은 **위아래 240px 가림 안**(결정 2026-10-18). 프레임은 실험 c 처럼 애니메이션 시각을 정해 찍는다(같은 입력 = 같은 영상). 글꼴 대체 검사 · 글 칸 넘침 검사는 카드 렌더링 것을 그대로
6. **합치기**: ffmpeg — 프레임 → H.264, 문장 오디오를 이어 AAC, 1080×1920 · 30fps · `+faststart`. 길이 · 무음 구간 검사(FR-MK-6 의 「길이 · 음량 · 멈춤」)
7. **업로드 폴더** · **폰으로 받기**(지금은 카드 PNG 만 내준다 → mp4 · srt 도 목록에 넣도록 넓힘) · 업로드 화면에 「인스타에서 AI 정보 표시를 켜세요」

예상 시간(실험 값으로): 프레임 캡처가 영상 1초당 약 2.7초(실험 c) → 30초 릴스 ≈ 80초 + 인코딩. TTS 는 실험 a 뒤에 채운다

## 5. 키 · 개인정보 · 동의

- **키**: 사용자 키는 **OS 키체인**(작업 규칙 · 결정 2026-10-13). 앱에 아직 키체인 코드가 없다(FR-AI-7 S) — macOS 는 `security` 명령(키체인 접근)으로 시작하고 Windows 는 나중(확인 못 함). 개발용은 `.env`(커밋 안 함, `.gitignore` 확인). **앱에 개발자 키를 넣지 않는다**
- **키가 없거나 무료 판이 끝났으면**(401 · 402 · 무료 모델 거절 등 — 실제 응답 모양은 실험 a 뒤에 적는다): 대본 · 무음 모션 · 자막까지 만들고 「음성은 만들지 못했어요 — 이유 · 할 일」 안내. 유료 모델로 저절로 바꾸지 않는다(헤더 값이 틀리면 유료 `s2.1-pro` 로 떨어진다는 문서 내용 때문에 **모델 값을 코드가 고정하고 응답의 모델을 확인**)
- **동의**: 무료 판은 「요청이 모델 개선에 쓰일 수 있음」을 화면에 알리고 체크해야 TTS 를 부른다(체크는 저장, 끄면 무음). 대본에 개인정보가 들어가지 않게 기존 개인정보 검사(redact)를 보내기 전에 한 번
- **목소리**: 이번 범위는 기본 목소리만. 음성 복제는 만들지 않고, 나중에 넣으면 「본인 목소리만」 안내 + 동의
- **업로드 안내**: 「인스타에서 AI 정보 표시를 켜세요」(정확한 메뉴 이름은 사용자 확인 뒤)

## 9. 키 넣는 법 (채팅에 붙여 넣지 않기)

1. fish.audio 에 로그인 → https://fish.audio/app/developers/get-started/ → 「Get your API key」 → 키를 **복사**(한 번만 보인다)
2. 터미널에서 레포 폴더로 가서 클립보드의 키를 `.env` 에 바로 쓴다(화면에 키가 찍히지 않음):
   ```sh
   cd ~/Claude/FirstFeed && printf 'FISH_AUDIO_API_KEY=%s\n' "$(pbpaste)" >> .env && chmod 600 .env && grep -c '^FISH_AUDIO_API_KEY=' .env
   ```
   마지막 숫자가 `1` 이면 들어간 것. `.env` 는 `.gitignore` 에 있어 커밋되지 않는다(`git check-ignore -v .env` 로 확인)
3. 나에게 「키 넣었어」라고만 알려 주면 `node --env-file=.env scripts/probe-fish-tts.ts` 를 한 번 돌린다(키 값은 보지 않는다)

## 11. 초보자 화면 흐름 (2026-11-05 제안)
