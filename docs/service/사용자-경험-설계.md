## 1. 「오늘 올릴 것」 홈

### 왜
지금 앱은 「정체성 → 브랜딩 → 템플릿 → 만들기」 탭을 사용자가 알아서 오가야 한다. 처음 며칠이 지나면 **매일 열 이유**가 없다. 30일 계획이 이미 있으니, 앱을 열면 「오늘은 이 칸」이 바로 보이고 만들기 → 올릴 준비 → 「올렸어요」까지 한 줄로 가게 한다. 올린 칸이 미리보기 격자에서 「계획」 → 「올림」으로 바뀌는 것이 보상이다.

### 화면 흐름

```
홈(새 탭, 앱 첫 화면)
 ├─ 30일 진행: 9칸 중 올림 n · 만듦 m · 계획 k   + 미리보기 격자(작게)
 ├─ 오늘 할 칸: [축] 제목            ← 예정일이 오늘 이전인 가장 앞 칸
 │    └─ 「이 칸으로 만들기」
 │         1. 소재 붙여넣기(그 칸 제목 · 축을 같이 보임)     ← 만들기는 소재 원문이 있어야 한다(근거 규칙)
 │         2. 표지 후보 — 그 칸 제목을 「원하는 제목」으로 넘김(기존 표지 API 의 requested)
 │         3. 본문 → 캡션 → 업로드 폴더 → 폰으로 받기(FR-PB-5)
 │         4. 「올렸어요」(날짜 기본 오늘)
 └─ 다음 칸 미리보기 · 「건너뛰기」(예정일을 뒤로)
```

- 칸 상태는 세 가지로 보인다: **계획**(아직 안 만듦, 지금의 점선 · 배지) / **만듦**(세트가 있음, 아직 안 올림) / **올림**(사용자가 「올렸어요」를 누름 — 「내가 표시」라고 작게). 인스타에 실제로 올라갔는지는 확인하지 않는다(비공식 자동화 금지 — PRD 비목표)
- 공유 이미지(FR-BR-7)도 세 상태를 그대로 쓴다

### 필요한 데이터

| 무엇 | 지금 | 더할 것 |
|---|---|---|
| 계획 칸 ↔ 만든 세트 | 잇지 않음(알려진 한계, CLAUDE.md 2026-10-21) | `plan_links(brand_id, slot_key, set_id)` — 칸은 판마다 새로 저장돼(고치면 새 판) 칸 번호가 아니라 **칸 열쇠**(만들 때 붙는 ID)로 잇는다 |
| 올림 | 없음 | `posts(id, brand_id, set_id, posted_at, marked_by='user')` — 세트에 붙인다(계획을 다시 만들어도 올린 기록은 남게) |
| 예정일 | 없음 | 계획 시작일(첫 「올렸어요」 날 또는 사용자가 고름) + 칸 순서 × 간격. 간격은 설정 `home.postEveryDays`(기본값은 사용자 결정) |
| 건너뛰기 | 없음 | 칸 열쇠별 미룬 날 수(같은 표 또는 slots_json) |

- 계획을 다시 만들 때 **만듦 · 올림 칸은 고정한 칸처럼 그대로 둔다**(지금의 「고정한 칸은 그대로」 규칙을 넓힘)
- 미리보기 격자 구성(composeGrid)의 순서는 「올림(오래된 순) → 만듦 → 계획」으로 — 인스타 격자는 최신이 왼쪽 위라 **실제 순서와 맞출지는 정해야 한다**(사용자)

## 2. 답할수록 채워지는 실시간 미리보기

### 왜
지금은 설문 8 + 인터뷰를 다 하고 프로필 → 브랜딩 → 템플릿 → 계획을 지나야 처음으로 「내 계정」이 보인다. 첫 5분 안에 **내 답이 계정이 되어 가는 것**이 보이면 끝까지 답할 이유가 생긴다(소개 페이지의 히어로가 보여 주는 장면을 실제 앱에서).

### 흐름 — 어느 시점에 무엇이 채워지나

| 시점 | 옆 패널에 채워지는 것 | AI 호출 | 대기(근거) |
|---|---|---|---|
| 설문 중 (S1~S8) | 계정 한 줄 자리 = S8 답 그대로, 보여 주는 방식(S6) → 프로필 사진 자리 모양, 격자 9칸은 빈칸 | **없음**(사용자 글 그대로 — 허용 출처 4번) | 0 |
| 인터뷰 1~2번째 답 | 답에서 따온 인용 한 줄씩 「근거 후보」로 쌓임 | 없음(꼬리질문은 원래 있음: sonnet, 평균 11.0초 AI 생성 · 14.4초 실제·공개 — `tests/results/2026-10-14-identity-followup-v2.md`) | 원래 대기 그대로 |
| 인터뷰 3번째 답 뒤 | **초안**: 아이디 후보 2 · 바이오 한 줄 · 색 분위기(말) — 패널에 「초안 · 확정 전」 | 안 A: 0회 더 / 안 B: sonnet 1회 | 안 A: 꼬리질문이 조금 길어짐(**짐작**, 안 잼) / 안 B: **짐작 10~20초**(꼬리질문과 같은 sonnet · 비슷한 출력 길이라고 보고) — 사용자가 다음 답을 쓰는 동안 돌면 기다림이 안 보인다 |
| 인터뷰 끝 | 초안 다시(답 전부로) | 안 A: 0 / 안 B: 1회 | 위와 같음 |
| 프로필 확정 | 축 이름 → 하이라이트 자리 | 원래 있음: 프로필 opus 평균 63초(`tests/results/2026-10-14-identity-profile-v2.md`) | 63초 |
| 브랜딩 | 아이디 · 이름 · 바이오(확정 후보) → 팔레트 · 글꼴 | 원래 있음: 글 40.4초 + 자기 평가 13.3초, 시각 45.5초(데모 1회, devlog 2026-10-22-03) | 차례로 약 99초 / 글 ∥ 시각이면 약 54초 |
| 계획 | 격자 9칸 표지 | 원래 있음: 26.6 · 33.4 · 34.6초(devlog 2026-10-22-03 · 2026-10-24-01) + 칸 표지 그리기(AI 없음, 칸마다 1초 안팎 — 화면 안내 문구) | 약 30초 + 약 9초 |

- 인터뷰 끝 → 격자가 다 찰 때까지(원래 있는 호출만): 63 + 약 99 + 약 30 + 약 9 ≈ **약 3분 20초**(차례로, `ai.concurrency` 기본 1). 브랜딩 글 · 시각을 같이 돌리면 약 2분 35초
- **더 드는 호출**: 안 A 0회, 안 B 1~2회(sonnet). 지금 한 사람이 끝까지 가는 데 드는 호출(데모 브랜드 10회, devlog 2026-10-22-03)에 비하면 안 B 도 10~20% 늘어난다

### 비용을 줄이는 방법
1. **초안은 저장하지 않고 자기 평가 없이** — 확정 결과는 늘 지금의 생성 → 규칙 → 자기 평가 흐름으로만 만든다. 초안은 「초안 · 확정 전」 표시(미리 만든 결과처럼 표시하는 원칙과 같음). 숫자 · 영문 근거 규칙만 건다(코드, 비용 없음)
2. **안 A: 꼬리질문 호출에 초안 칸을 얹는다** — 호출 수가 그대로다. 대신 꼬리질문 프롬프트가 길어지고(새 판), 질문 품질이 흔들리지 않는지 같은 세트로 다시 재야 한다(꼬리질문 측정 `npm run eval:followup`)
3. **바뀐 게 있을 때만** — 답이 늘지 않았으면 다시 부르지 않는다. 3번째 답 · 마지막에만(2번)
4. **sonnet 으로** — 초안은 확정이 아니라서 opus 를 쓰지 않는다(과제별 모델 설정 `ai.taskModels`)
5. **AI 없이 채울 수 있는 것부터** — 계정 한 줄(S8) · 보여 주는 방식(S6) · 빈 격자 · 근거 후보 인용은 코드로 바로

### FR 후보
- FR-ID-7 답할수록 채워지는 미리보기 — 설문 · 인터뷰 화면 옆 패널, 설문 값은 바로, 초안은 「초안 · 확정 전」, 확정은 지금 흐름 그대로
- FR-BR-6 의 확장으로 둘 수도 있다(같은 격자 컴포넌트)

## 4. 무엇이 먼저인가 — 표

일의 양은 이 레포에서 비슷한 일을 했던 경험으로 본 **짐작**이다: 작음 = 한 세션 안, 중 = 1~2세션, 큼 = 2세션 넘게.

| 후보 | 사용자 매력 | 대회 효과 | 일의 양 | 메모 |
|---|---|---|---|---|
| 「오늘 올릴 것」 홈 (FR-HM-1~4) | **높음** — 매일 열 이유, 「계획 → 올림」으로 칸이 바뀌는 보상 | 최종 「결과물 완성도 30」: 한 번 쓰고 끝나는 도구가 아니라 30일을 같이 가는 도구로 시연 · 실사용자 2명(11-15)과 바로 이어짐 | **중~큼** — 표 2개 · 홈 화면 · 칸 ↔ 세트 잇기 · 미리보기 상태 3가지 | 계획 칸 ↔ 세트를 잇는 알려진 한계를 같이 푼다 |
| 답할수록 채워지는 미리보기 (FR-ID-7) | **높음** — 첫 5분의 「와」 | 중간 「독창성 30」의 ⓪ 미리보기를 더 앞으로 · 최종 시연의 첫 장면 | **큼** — 패널 · 초안 프롬프트(새 판) · 측정(안 A 면 꼬리질문 다시 재기) | AI 호출 0~2회 더(안 A/B) |
| 댓글 키워드 · 고정 댓글 · DM (FR-MK-9) | 중 — 실제 운영 계정이 많이 쓰는 방식 | 낮음~중 — 프롬프트 · 규칙 사례 하나 더 | 중 — 프롬프트 1 · 키워드 일치 규칙 · 마무리 장 | PRD 에 이미 S 로 있음 |

- 짐작으로 본 순서(사용자가 고른다): **AI 대기 단계 표시(작음) → 오늘 올릴 것 홈 → 디자인 통일 → 실시간 미리보기 → FR-MK-9**. 홈이 실사용(11-15 실사용자 2명)과 가장 가깝고, 실시간 미리보기는 측정이 필요해 크다
