# 서비스화 계획 — 대회 뒤 실제로 여러 사람이 쓰게 할 때 다시 볼 것

> 2026-10-24 새로 만듦(사용자 결정 「서비스화 계획에 HTTPS 검토 항목」 — 이 이름의 문서가 레포에 없어서 만들었다). 대회 일정 · 범위는 [PRD 9장](../PRD.md), 화면 · 흐름 설계는 [사용자-경험-설계.md](사용자-경험-설계.md).
> 지금 버전에서 하지 않는 것만 적는다. 항목마다 「왜 지금 안 하나」를 같이.

## 보안

- **폰으로 받기(FR-PB-5)의 HTTPS 검토** — 지금은 같은 와이파이 안에서 `http://<사설 주소>:<포트>` 로 연다. 같은 네트워크에서 엿들으면 그림 · 캡션과 주소(토큰)가 보인다(CLAUDE.md 2026-10-24 · 폰으로 받기의 알려진 한계)
  - 왜 지금 안 하나: 사설 주소에는 공인 인증서를 받을 수 없고, 자체 서명 인증서는 휴대폰 브라우저가 경고를 띄워 오히려 「경고를 무시하고 들어가세요」를 가르치게 된다
  - 검토할 길(확인 전 — 각각 실제로 되는지 · 비용을 재야 한다): ① 이 컴퓨터가 처음 한 번 로컬 인증 기관을 만들고 휴대폰에 설치(설치 단계가 입문자에게 어렵다) ② 휴대폰으로 보내는 대신 사용자가 이미 쓰는 클라우드(사진 앱 공유 앨범 · 드라이브)에 올리게 안내 ③ 공용 중계(외부 서버가 생겨 「로컬 앱 · 본인 구독으로만 돈다」 원칙과 부딪힘)
  - 그때까지: 화면에 「카페 같은 공용 와이파이에서는 쓰지 마세요」(2026-10-24), 10분 · 처음 연 기기 하나 · 그 폴더 파일만
