첨부한 파일 하나에 내가 혼자 개발 중인 로컬 앱 FirstFeed(인스타그램 입문자용)의 기획 자료 4개가 들어 있어. 각 자료는 "# [자료 N]" 제목으로 시작해.

- 자료 1: 지금 PRD(v0.1). 기능 요구사항 58개, FR 번호와 수용 기준이 있어.
- 자료 2: PRD 이후에 개발하면서 내린 결정.
- 자료 3: 10월 18일 기준 구현 상태(끝남 / 진행 / 안 함).
- 자료 4: 지금까지 정한 제품 방향("정해진 것")과 아직 안 정한 것("정할 것").

목표는 FirstFeed의 제품 PRD를 v0.2로 완성도 있게 다시 정리하는 거야. 발표나 과제용 문서가 아니라, 앞으로 개발할 때 기준으로 쓸 제품 문서야.

규칙
1. FR 번호(FR-XX-n)는 바꾸지 마. 코드, 테스트, 개발 기록이 이 번호를 쓰고 있어. 새 요구사항이 생기면 같은 규칙으로 다음 번호를 붙여 줘.
2. 자료 4의 "정해진 것"은 그대로 반영하고, "정할 것"은 네가 정하지 말고 나한테 질문해.
3. 자료에 없는 숫자, 날짜, 외부 서비스 정책은 지어내지 마. 필요하면 질문해.
4. 자료 2의 결정은 자료 1보다 나중에 내린 거야. 둘이 다르면 자료 2를 따르고, 다른 곳은 따로 목록으로 보여 줘.
5. 목차와 구성은 다시 짜도 돼. 대신 마지막에 v0.1 → v0.2 변경 내역(무엇을, 왜, 근거 자료)을 표로 붙여 줘.

진행 순서
- 1단계: 자료를 읽고 제품 PRD로서 비어 있는 곳을 찾아 줘. ① 자료 2·4와 충돌하는 부분 ② 분류가 안 된 요구사항 ③ 수용 기준을 고쳐야 하는 요구사항 ④ 정책이나 예외 상황이 비어 있는 곳(예: AI 생성이 실패했을 때, 사용자가 중간에 그만뒀을 때, 입력 자료가 부족할 때). 표로 정리한 다음, 결정이 필요한 질문을 중요한 순서대로 물어봐.
- 2단계: 내 답을 받으면 PRD v0.2 전체를 써 줘. 문제 정의, 목표와 하지 않을 것, 대상 사용자, 핵심 사용자 흐름, 기능 요구사항(우선순위와 수용 기준), 화면 구성, 비기능 요구사항, 성공 지표, 출시 계획과 일정, 위험, 아직 정하지 못한 것 순서로.
- 3단계: "최종까지 반드시" 기능의 기능명세서와, 기본 흐름(정체성 찾기 → 브랜딩 → 카드뉴스·캡션 → 업로드 → 성과 입력 → 프로필 갱신 제안)의 유저플로우를 만들어 줘. 화면 이름은 PRD 8장(홈, 브랜드, 발굴, 만들기, 창고, 운영, 성과, 설정)을 따르고, 이번 버전에서 쓰지 않는 메뉴는 따로 표시해 줘.

지금은 1단계만 해 줘.
