## 1 Claude CLI 기반 로컬 AI 연결 및 실행 준비

중요도 높음 · 기획 상태 기획 확정

Claude를 구독하는 로컬 사용자가 별도 서비스 계정 로그인 없이 자신의 컴퓨터에서 AI 기능을 사용할 수 있도록 한다. Claude Code CLI의 설치·로그인·구독 상태와 실행 준비를 확인하고 연결 불가 시 다음 행동을 안내한다. 다른 공급자와 API 키 경로는 기본 흐름 밖의 여유 범위다. 연계 FR: FR-AI-1·2·4, FR-AC-6.

**수용 기준**

1. ○ 앱은 Claude Code CLI의 설치 여부, 로그인 상태, 구독 사용 가능 여부를 사용자에게 표시한다.
2. ○ 구독 또는 연결 조건을 충족하지 않으면 AI 실행 전에 호출을 막고 차단 사유와 다음 조치를 한국어로 안내한다.
3. ○ 사용자는 Node 버전과 Claude 로그인 상태를 점검하는 명령 및 앱을 한 번에 시작하는 명령을 사용할 수 있다.

### 1.1 Claude CLI 연결 상태 점검

중요도 높음 · 기획 상태 기획 확정

Claude 구독 로컬 사용자는 Claude Code CLI의 설치, 로그인 및 구독 상태와 설치 점검 명령을 확인한다. 연결할 수 없으면 차단 사유와 다음 행동을 안내받고 앱을 한 번에 시작하는 명령을 사용할 수 있다. 다른 공급자와 API 키 연결은 포함하지 않는다. 연계 FR: FR-AI-1·FR-AC-6.

**[기능의 근거]** 주 사용자는 별도 서비스 계정 로그인 없이 자신의 Claude 구독으로 AI 기능을 사용해야 한다.

**[개발 준비 슬롯]**

- **선행조건**: 사용자의 컴퓨터에 Claude Code CLI를 설치할 수 있어야 한다.
- **트리거**: 사용자가 설정에서 Claude 연결 점검을 시작하거나 AI 실행을 시도한다.
- **동작**:
  - 앱은 CLI 설치, 로그인 및 구독 상태를 확인한다.
  - 앱은 연결 불가 사유에 맞는 다음 행동을 안내한다.
- **결과**: 사용자는 AI 실행 가능 여부와 차단 사유를 확인한다.
- **예외**: 구독 상태가 아니면 실행 전에 요청을 차단하고 blocked 이력을 남긴다.
- **표시**: 연결 상태와 문제별 해결 안내를 한국어로 표시한다.
- **권한 & 접근**: 로컬 사용자는 자신의 Claude CLI 연결만 점검한다.

- **데이터**: 연결 점검 이력은 상태와 차단 사유를 저장한다.

### 1.2 공통 AI 작업 실행 어댑터

중요도 높음 · 기획 상태 기획 제안

앱은 Claude CLI를 통해 생성 작업을 실행하고 검증된 JSON 응답을 공통 형식으로 전달한다. 공통 형식은 가짜 공급자 테스트로 확인하고, 실제 다중 공급자 호환성은 이 기능에서 판정하지 않는다. 연계 FR: FR-AI-2·FR-AI-4.

**[기능의 근거]** 브랜드 프로필과 콘텐츠 생성 흐름은 안정적으로 구조화된 AI 응답을 받아야 한다.

**[성공 기준]** 고정 테스트 세트에서 AI 작업은 1회 통과율 70% 이상, 2회 재작성 이내 통과율 95% 이상을 목표로 한다.

**[개발 준비 슬롯]**

- **선행조건**:
  - Claude CLI 연결 점검이 통과해야 한다.
  - 작업별 입력과 JSON 응답 계약이 준비되어야 한다.
- **트리거**: 사용자가 AI 기반 생성 작업을 실행한다.
- **동작**:
  - 앱은 안전 모드와 빈 임시 폴더에서 CLI를 실행한다.
  - 앱은 응답을 공통 JSON 계약으로 검증한다.
  - 앱은 가짜 공급자 테스트로 요청과 응답의 공통 JSON 계약을 확인한다.
- **결과**: 검증된 JSON 응답이 다음 생성 또는 검증 단계에 전달된다.
- **예외**:
  - JSON 형식 오류가 나면 1회만 복구를 재시도한다.
  - 복구에 실패한 응답은 저장하지 않는다.
- **표시**: 실행 상태와 실패 결과를 사용자에게 표시한다.
- **권한 & 접근**: 연결된 로컬 사용자만 자신의 구독으로 AI 작업을 실행한다.
- **비즈니스 규칙**: 실제 두 공급자로 같은 작업을 실행하는 검증은 FR-AI-6의 여유 범위로 둔다.
- **데이터**: 실행 이력은 작업 유형, 상태, 호출 수 및 단계별 소요 시간을 저장한다.

## 2 근거 기반 브랜드 정체성 수립

중요도 높음 · 기획 상태 기획 제안

인스타 입문자는 설문·AI 인터뷰와 자신이 제공한 포트폴리오·이력서 등의 자료를 근거로 계정 방향을 정한다. 근거가 확인되는 브랜드 프로필을 확정해 이후 콘텐츠 생성에 사용한다. 읽지 못한 자료는 프로필의 근거에 포함하지 않는다. 연계 FR: FR-ID-1~6.

**수용 기준**

1. ✓ 사용자는 8문항 설문과 한 번에 한 질문씩 진행되는 AI 인터뷰를 통해 계정 목표와 관심 분야를 입력할 수 있다.
2. ✓ 브랜드 프로필은 근거 인용이 있는 콘텐츠 축 3~5개를 포함하며, 근거 없는 축은 확정 결과에서 제외된다.
3. ✓ 근거 있는 축이 3개 미만이면 추가 인터뷰 또는 실패 안내를 제공하며, 인터뷰 한도 소진 후 근거 없는 프로필을 확정하지 않는다.
4. ○ 포트폴리오 PDF·이력서·깃허브 주소·블로그 주소·기존 게시물 캡처를 근거로 활용하고 근거 문장에 파일명·쪽 등 확인 가능한 출처를 표시한다. 읽지 못한 자료는 근거로 삼지 않는다.

### 2.1 설문과 AI 인터뷰 기반 정체성 탐색

중요도 높음 · 기획 상태 기획 제안

인스타 입문자는 짧은 설문과 한 번에 한 질문씩 진행하는 AI 인터뷰로 계정 방향의 근거를 마련한다. 앱은 부족한 축만 추가로 질문하고 중복 질문을 피한다. 사용자 자료의 추가는 별도 기능으로 제공하며 설문·인터뷰 자체와 혼동하지 않는다. 연계 FR: FR-ID-1·2.

**[기능의 근거]** 계정 정체성이 넓어 소재가 고갈되는 문제를 해결하려면 사용자가 자신의 방향을 먼저 정해야 한다.

**[개발 준비 슬롯]**

- **선행조건**: 사용자가 로컬 브랜드 작업공간을 시작해야 한다.
- **트리거**: 사용자가 브랜드 화면에서 설문 또는 인터뷰를 시작한다.
- **동작**:
  - 앱은 계정 목표, 관심 분야, 노출 방식 등을 포함한 8문항 설문을 제공한다.
  - AI는 3~10개 범위에서 한 번에 한 질문씩 인터뷰한다.
  - 사용자가 잘 모르겠다고 답하면 선택지를 제시한다.
- **결과**: 브랜드 프로필 초안에 쓸 사용자 답변 근거가 축적된다.
- **예외**:
  - 예시 답변만으로는 브랜드 축의 단독 근거로 사용하지 않는다.
  - 10턴을 소진해도 충분한 축이 없으면 실패를 안내한다.
- **표시**: 설문 진행 상태와 현재 인터뷰 질문을 표시한다.
- **권한 & 접근**: 로컬 사용자는 자신의 설문과 인터뷰 답변을 작성한다.
- **비즈니스 규칙**:
  - 설문은 2분 안에 마칠 수 있는 범위로 구성한다.
  - 근거가 부족한 축이 있을 때만 인터뷰 한도 안에서 추가 질문한다.
- **데이터**: 설문 답변과 인터뷰 턴은 입력 시각 및 출처 유형과 함께 저장한다.

### 2.2 근거 인용 브랜드 프로필 확정과 이력 관리

중요도 높음 · 기획 상태 기획 제안

**[기능의 근거]** 브랜드 프로필을 콘텐츠와 성과 개선까지 잇는 공통 입력으로 사용해 일관된 계정 방향을 유지해야 한다.

**[성공 기준]** 처음 쓰는 사람이 30분 안에 브랜드 프로필·고정 템플릿·첫 카드뉴스 1세트를 얻는다.

**[개발 준비 슬롯]**

- **결과**: 확정된 활성 프로필 판이 이후 생성의 축, 말투 및 피할 요소 입력으로 사용된다.
- **예외**:

- **비즈니스 규칙**:

- **데이터**:
  - 프로필 판은 계정 정의, 타깃, 축, 말투, 피할 요소, 인용 및 활성 여부를 저장한다.
  - 항목별 출처와 생성 사유를 저장한다.

### 2.3 브랜드 근거 자료 올리기

- **트리거**:

- **동작**:

- **결과**: 사용자가 제공하고 읽기에 성공한 자료는 브랜드 프로필 근거 후보로 연결된다.

- **표시**:

## 3 일관된 브랜딩 키트와 고정 템플릿

### 3.1 브랜드 소개와 시각 키트 관리

중요도 높음 · 기획 상태 기획 제안

사용자는 확정 브랜드 프로필을 바탕으로 아이디·표시 이름·바이오·색 팔레트·폰트 조합을 선택하고 프로필 사진과 하이라이트 커버 시안을 관리한다. 만든 그림을 올려 적용하는 경로를 포함하되 하이라이트 커버 업로드는 아직 미완료로 표시한다. 격자 미리보기는 포함하지 않는다. 연계 FR: FR-BR-1·2·3·4.

**[기능의 근거]** 게시물마다 디자인이 달라 일관된 계정으로 보이지 않는 문제를 해결하려면 공통 시각 기준이 필요하다.

**[개발 준비 슬롯]**

- **선행조건**: 확정된 브랜드 프로필이 있어야 한다.
- **트리거**: 사용자가 브랜딩 키트 후보 생성을 시작하거나 후보를 선택한다.
- **동작**:
  - 앱은 아이디, 표시 이름, 바이오 후보를 각각 5개 제안한다.
  - 앱은 색 팔레트와 제목·본문 폰트 조합을 각각 3안 제안한다.
  - 앱은 프로필 사진과 하이라이트 커버의 글자형 시안 및 크기·비율·no text를 포함하는 그림 프롬프트를 제공한다.
  - 사용자는 만든 그림을 올려 시안에 적용한다.
- **결과**:
  - 선택한 이름, 바이오, 색상 및 폰트가 브랜드 키트에 저장된다.
  - 사용자가 적용한 프로필 사진·하이라이트 커버 그림은 해당 시안에 반영된다.
- **예외**:
  - 명암비 4.5:1 미만의 글자와 배경 조합은 제외한다.
  - 바이오에는 URL을 넣지 않는다.
  - 프로필 사진에는 낯선 실사 인물이나 신체를 제안하지 않는다.
- **표시**:
  - 후보별 브랜드 프로필 반영 내용과 폰트 라이선스 출처를 표시한다.
  - 하이라이트 커버 업로드는 아직 미완료로 표시한다.
  - 얼굴 공개 계정에는 사용자 본인 사진 사용을 안내한다.
- **권한 & 접근**: 로컬 사용자는 자신의 브랜딩 키트 후보를 선택하고 변경한다.
- **비즈니스 규칙**:
  - 아이디와 표시 이름은 30자, 바이오는 링크 자리 20자를 포함해 150자로 보수적으로 검사한다.
  - 폰트는 OFL 확인 목록의 상업적 사용 가능 조합만 제안한다.
- **데이터**:
  - 브랜딩 키트는 선택한 이름, 바이오, 색상 역할별 값 및 제목·본문 폰트를 저장한다.
  - 프로필 사진과 하이라이트 커버 시안은 그림 프롬프트와 사용자가 적용한 그림의 참조를 갖는다.

### 3.2 브랜드 적용 템플릿 고정과 렌더링 검증

중요도 높음 · 기획 상태 기획 확정

사용자는 브랜드 색과 폰트가 적용된 카드뉴스 및 릴스 표지 템플릿 시안을 고정해 이후 결과에 계속 적용할 수 있다. 앱은 렌더링 결과의 넘침, 겹침 및 안전 영역을 검사한다. 추가 본문 배치 유형과 격자 미리보기는 포함하지 않는다. 연계 FR: FR-TP-1·3·4.

**[기능의 근거]** 고정된 템플릿과 출력 검증은 계정의 시각적 일관성과 화면 품질을 보장하는 데 필요하다.

**[성공 기준]** 기준 브라우저의 테스트 PNG에서 글자 잘림과 겹침 0건을 목표로 한다.

**[개발 준비 슬롯]**

- **선행조건**: 선택된 브랜딩 키트와 사용 가능한 폰트가 있어야 한다.
- **트리거**: 사용자가 템플릿 시안을 고정하거나 콘텐츠 렌더링을 요청한다.
- **동작**:
  - 앱은 3~5종 범위의 기존 틀을 브랜드 색과 폰트로 변형한다.
  - 앱은 브라우저 DOM으로 넘침, 겹침 및 안전 영역을 측정하고 단계적으로 축소한다.
- **결과**:
  - 고정한 템플릿 판이 이후 콘텐츠 결과에 적용된다.
  - 통과한 렌더링 결과가 PNG 출력에 사용된다.
- **예외**:
  - 폰트 로드에 실패하면 PNG를 만들지 않고 원인을 표시한다.
  - 축소 후에도 넘치면 직접 수정을 안내한다.
- **표시**:
  - 시안과 렌더링 검사 결과를 표시한다.
  - 기준 브라우저가 아닌 Chrome 결과에는 기준 아님을 표시한다.
- **권한 & 접근**: 로컬 사용자는 템플릿 시안을 고정하고 새 판으로 변경한다.
- **비즈니스 규칙**:
  - 카드 규격은 1080×1350이고 릴스 표지 규격은 1080×1920이다.
  - 카드 좌우 34px 및 릴스 위아래 240px 안전 영역을 검사한다.
- **데이터**:
  - 템플릿 판은 브랜드 키트 참조, 규격, 고정 여부 및 버전을 저장한다.
  - PNG마다 사용 브라우저와 버전을 기록한다.

## 4 사실 검증된 카드뉴스와 캡션 생성

중요도 높음 · 기획 상태 기획 제안

사용자는 소재 원문과 확정 프로필로 카드뉴스·그림 프롬프트·캡션을 만들고 지정한 카드를 말로 고칠 수 있다. 숫자·날짜·이름 등의 근거를 대조해 미검증 결과를 확정하거나 내보내지 않는다. 자동 이미지·릴스 영상 생성과 댓글·DM 자동 전송은 포함하지 않는다. 연계 FR: FR-MK-1·2·3·7·8.

**수용 기준**

1. ○ 사용자는 고정 템플릿에서 제목 후보를 고르고 표지·본문·마무리 카드뉴스와 그림 프롬프트를 생성하며, 캡션 해시태그는 설정값 상한으로 제한된다.
2. ✓ 카드와 캡션의 숫자·버전·날짜·영문 이름은 소재 원문, 브랜드 프로필·키트, 구조상 숫자 또는 사용자 직접 입력 문장에만 근거해야 한다.
3. ✓ 원문 밖의 용어 풀이·비유는 별도로 표시되며, 사용자가 확인하거나 직접 수정하기 전에는 업로드용 결과를 내보낼 수 없다.
4. ○ 사용자는 지정한 카드만 말로 다시 쓰고 그리며 표지를 유지하고 이전 판으로 되돌릴 수 있다.

### 4.1 브랜드 기반 카드뉴스와 캡션 생성

중요도 높음 · 기획 상태 기획 제안

사용자는 소재 원문과 확정 브랜드 프로필·고정 템플릿을 입력으로 카드뉴스와 캡션·그림 프롬프트를 생성한다. 캡션 해시태그는 설정값 상한을 따르고 사용자가 그림을 표지에 올리면 그 표지만 다시 그린다. 자동 이미지 생성과 릴스 영상 생성은 포함하지 않는다. 연계 FR: FR-MK-1·7·8.

**[기능의 근거]** 사용자는 매번 소재와 디자인을 새로 결정하지 않고 일관된 카드뉴스를 만들어야 한다.

**[성공 기준]** 카드뉴스 7장 생성과 렌더링을 5분 이내에 완료하는 목표를 실제 측정으로 검증한다.

**[개발 준비 슬롯]**

- **선행조건**:
  - 확정 브랜드 프로필과 고정 템플릿이 있어야 한다.
  - 사용자가 제공한 소재 원문이 있어야 한다.
- **트리거**: 사용자가 만들기 화면에서 카드뉴스 생성을 요청한다.
- **동작**:
  - 앱은 표지 제목 6개를 제안하고 사용자의 선택을 받는다.
  - 앱은 소재 양에 맞춘 본문 카드와 마무리를 생성한다.
  - 앱은 카드별 영어 그림 프롬프트와 캡션을 생성한다.
  - 사용자가 그림을 표지에 올리면 그 표지만 다시 그린다.
- **결과**:
  - 검증 대기 상태의 카드뉴스, 캡션 및 그림 프롬프트가 생성된다.
  - 표지 그림을 올려 다시 그릴 때 표지 이외의 카드는 유지된다.
- **예외**:
  - 고정 템플릿이 없으면 카드뉴스를 생성하지 않는다.
  - 카드 그림 프롬프트는 실사 사람·신체와 실존 인물 지시를 포함하지 않는다.
  - 사용자가 표지 그림을 올리지 않으면 브랜드 주색을 바탕으로 사용한다.
- **표시**: 표지 제목 후보와 카드별 생성 결과를 표시한다.
- **권한 & 접근**: 로컬 사용자는 자신의 소재로 콘텐츠 생성을 실행한다.
- **비즈니스 규칙**:
  - 표지는 2줄 이내로 작성한다.
  - 본문 카드는 한 장에 한 가지 말과 원문 근거 인용 하나를 갖는다.
  - 캡션은 첫 줄 훅, 핵심 문장, 댓글 유도 및 해시태그를 포함한다.
  - 캡션의 해시태그는 설정값 상한으로 자른다.
- **데이터**: 콘텐츠는 소재 원문, 프로필 판, 템플릿 판, 카드 목록, 캡션 및 그림 프롬프트를 연결해 저장한다.

### 4.2 콘텐츠 사실 근거 대조와 내보내기 차단

중요도 높음 · 기획 상태 기획 확정

앱은 생성된 카드뉴스와 캡션의 숫자, 날짜, 버전 및 이름을 허용된 출처와 대조해 사실 오류를 차단한다. 근거 없는 값 또는 확인되지 않은 풀이가 남은 결과는 재작성하거나 사용자의 확인 전까지 내보내지 않는다. 자동 이미지 생성은 이 검증 범위에 포함하지 않는다. 연계 FR: FR-MK-2.

**[기능의 근거]** 허위 사실이나 근거 없는 수치가 포함된 콘텐츠는 사용자 신뢰와 게시 품질을 해친다.

**[성공 기준]** 고정 테스트 세트에서 허용 출처 밖 숫자와 이름이 0건이어야 한다.

**[개발 준비 슬롯]**

- **선행조건**: 카드뉴스 또는 캡션 생성 결과와 원문 근거가 있어야 한다.
- **트리거**: 생성 결과가 확정 저장 또는 내보내기 단계로 이동한다.
- **동작**:
  - 앱은 숫자, 버전, 날짜 및 영문 이름을 허용 출처와 대조한다.
  - 위반이 있으면 규칙 재작성을 최대 2회 수행한다.
- **결과**: 검증 통과 결과만 확정 저장과 내보내기 대상으로 전환된다.
- **예외**:
  - 재작성 한도 안에 통과하지 못하면 결과를 저장하지 않는다.
  - 소재 밖 풀이 또는 비유는 확인 전 내보내지 않는다.
- **표시**:
  - 근거 인용과 확인이 필요한 풀이를 구분해 표시한다.
  - 검증 실패 항목을 표시한다.
- **권한 & 접근**: 로컬 사용자는 검증 결과를 확인하고 직접 수정할 수 있다.
- **비즈니스 규칙**:
  - 허용 출처는 소재 원문, 브랜드 프로필·키트, 구조상 숫자 및 사용자 직접 입력 문장이다.
  - 사용자가 직접 수정한 문장은 사용자 입력으로 취급하되 고정 형식과 넘침 검사는 유지한다.
- **데이터**: 검증 기록은 검사 대상, 근거 출처, 통과 상태 및 재작성 횟수를 저장한다.

### 4.3 지정 카드 말로 고치기

중요도 높음 · 기획 상태 기획 작성중

사용자는 생성한 카드뉴스의 특정 카드에 말로 수정 지시를 내려 그 카드의 글과 그림을 다시 만든다. 수정 대상이 아닌 카드와 표지는 유지하며 이전 판으로 되돌릴 수 있다. 카드뉴스 전체를 새로 생성하거나 다른 카드까지 함께 바꾸지는 않는다. 연계 FR: FR-MK-3(F).

**[기능의 근거]** 만든 카드의 한 부분만 고쳐야 할 때 전체를 다시 만들면 사용자가 확정한 제목과 다른 카드의 일관성이 깨진다.

**[개발 준비 슬롯]**

- **선행조건**: 수정할 카드뉴스와 사용자가 지정한 카드가 존재해야 한다.
- **트리거**:
  - 사용자가 카드 하나를 지정하고 말로 수정 지시를 제출한다.
  - 사용자가 이전 판으로 되돌리기를 선택한다.
- **동작**:
  - 앱은 지정된 카드의 글을 수정 지시에 따라 다시 쓰고 그 카드만 다시 그린다.
  - 앱은 표지와 수정 대상이 아닌 카드의 내용을 유지한다.
  - 앱은 이전 판으로 되돌리기를 제공한다.
- **결과**:
  - 수정한 카드의 새 판이 카드뉴스에 반영된다.
  - 되돌리면 이전 판의 내용이 다시 표시된다.
- **예외**: 사실 대조 또는 렌더링 검사를 통과하지 못한 수정 결과는 확정하지 않는다.
- **표시**:
  - 사용자는 수정한 카드와 표지가 유지된 결과를 확인한다.
  - 사용자는 수정 전 판으로 되돌릴 수 있는 동작을 본다.
- **권한 & 접근**: 로컬 사용자는 자신의 카드뉴스에서 지정한 카드만 수정하고 되돌릴 수 있다.
- **비즈니스 규칙**:
  - 표지와 수정 대상이 아닌 카드는 이번 수정의 대상이 아니다.
  - 수정한 내용도 카드뉴스의 사실 근거와 렌더링 검사를 거친다.
- **데이터**: 카드 판은 대상 카드, 이전 판 참조, 수정 지시, 생성 시각 및 확정 상태를 구분한다.

## 5 직접 게시를 위한 업로드 결과물 내보내기

중요도 높음 · 기획 상태 기획 확정

사용자는 검증된 카드뉴스를 직접 게시하기 위해 업로드 이미지와 보조 파일을 분리해 로컬 폴더로 내보낸다. 계정 연동·예약 발행·자동 업로드는 포함하지 않는다. 실제 업로드 창에서 다중 선택 파일의 순서는 확인 전까지 보장하지 않는다. 연계 FR: FR-PB-1.

**수용 기준**

1. ○ 내보내기 시 업로드 폴더에는 번호순 PNG 이미지만 저장되고, 캡션·그림 프롬프트·확인 설명 파일은 업로드 폴더 밖에 저장된다.
2. ○ 이미지 파일명과 수정 시각은 카드 순서와 일치하며, 같은 이름의 결과 폴더가 이미 있으면 기존 파일을 덮어쓰지 않는다.
3. ○ 풀이 확인 또는 필요한 직접 수정이 완료되지 않은 콘텐츠는 업로드용 폴더로 내보낼 수 없다.

### 5.1 직접 게시용 업로드 패키지 내보내기

중요도 높음 · 기획 상태 기획 확정

사용자는 검증된 카드뉴스를 인스타에 직접 게시하도록 순서가 정해진 이미지와 보조 파일을 로컬 폴더로 내보낸다. 앱은 업로드할 그림과 캡션·프롬프트·확인 설명 파일을 분리한다. 계정 연동, 예약 발행 및 자동 업로드는 포함하지 않는다. 연계 FR: FR-PB-1.

**[기능의 근거]** 사용자가 생성 결과를 실제 인스타 게시 단계로 안전하게 이어 가려면 파일 구조가 정리되어야 한다.

**[성공 기준]** 최종 기본 흐름 시연에서 카드뉴스 1세트의 업로드 패키지를 직접 게시 준비까지 완성한다.

**[개발 준비 슬롯]**

  - 필요한 사용자 직접 수정과 풀이 확인이 끝나야 한다.
- **트리거**: 사용자가 콘텐츠의 업로드 준비 내보내기를 선택한다.
- **동작**:
  - 앱은 업로드 루트 아래 날짜와 표지 제목으로 폴더를 만든다.

- **결과**: 사용자는 정렬된 이미지와 보조 파일을 이용해 직접 인스타에 게시할 수 있다.

- **표시**: 생성된 폴더 위치와 내보낸 파일 목록을 표시한다.
- **권한 & 접근**: 로컬 사용자는 자신의 검증 통과 콘텐츠만 내보낼 수 있다.
- **비즈니스 규칙**:
  - 기본 업로드 위치는 ~/Downloads/FirstFeed/이며 이 경로 밖에는 쓰지 않는다.
  - 실제 인스타 업로드 창의 다중 파일 선택 순서는 확정 동작으로 보장하지 않는다.
- **데이터**: 내보내기 이력은 콘텐츠 참조, 경로, 파일 목록 및 생성 시각을 저장한다.

## 6 성과 직접 입력과 프로필 갱신 제안

중요도 높음 · 기획 상태 기획 확정

사용자는 인사이트 캡처로 성과를 확인·입력하고 유효한 지표를 분석해 프로필 갱신 제안을 받는다. 읽지 못한 값은 0으로 대체하지 않으며 수락한 변경만 제목 생성에 반영한다. 공식 API 수집과 발굴 추천 연계는 이번 버전에서 제외한다. 연계 FR: FR-IN-2~6.

**수용 기준**

1. ○ 사용자는 인사이트 캡처에서 읽은 숫자와 원본 위치를 함께 확인하고, 값을 수정하거나 비운 채로 저장할 수 있으며 빈 값은 ‘입력 안 됨’으로 표시된다.
2. ○ 게시 후 48시간이 지난 게시물만 분석 대상에 포함되고, 빈 분자·분모가 있는 지표는 평균 계산에서 제외된다.
3. ○ 축·형식·제목 유형별 분석은 유효 표본이 3개 이상일 때만 결론을 제시하며, 다음 행동 제안은 유효 수치를 근거로 최대 3개까지 제공한다.
4. ○ 사용자가 제안을 수락한 경우에만 프로필과 제목 생성 입력을 갱신하고, 해당 변경은 ‘성과에서 온 변경’ 이력으로 남으며 3주 후 자동 제외된다.

### 6.1 인사이트 캡처 기반 성과 직접 입력

중요도 높음 · 기획 상태 기획 확정

사용자는 인스타 인사이트 캡처에서 읽은 성과 수치와 원본 위치를 확인하고 저장한다. 읽지 못한 값은 직접 보완하거나 빈 값으로 저장할 수 있으며, 앱은 이를 0으로 바꾸지 않는다. 공식 API 자동 수집은 포함하지 않는다. 연계 FR: FR-IN-2.

**[기능의 근거]** 사용자는 게시 후 숫자를 확인하더라도 신뢰할 수 있는 성과 데이터를 직접 정리할 방법이 필요하다.

**[개발 준비 슬롯]**

- **선행조건**: 사용자가 게시물과 해당 인사이트 캡처를 가지고 있어야 한다.
- **트리거**: 사용자가 성과 화면에서 캡처를 추가하고 입력 확인을 시작한다.
- **동작**:
  - 앱은 캡처에서 읽은 숫자와 원본 위치를 나란히 표시한다.
  - 사용자는 값을 수정하거나 비운 채 저장한다.
- **결과**: 게시물별 성과 기록과 값의 원본 위치가 저장된다.
- **예외**: 읽지 못한 수치는 빈 값으로 유지하고 0으로 대체하지 않는다.
- **표시**:
  - 빈 값은 입력 안 됨으로 표시한다.
  - 읽은 위치와 입력값을 함께 표시한다.
- **권한 & 접근**: 로컬 사용자는 자신의 성과 기록을 입력하고 수정한다.
- **비즈니스 규칙**:
  - 자동 성과 수집과 공식 API 연동은 제공하지 않는다.
  - 빈 값은 분석 계산에서 0으로 취급하지 않는다.
- **데이터**: 성과 기록은 게시물 참조, 지표별 값, 빈 값 상태, 원본 위치 및 입력 시각을 저장한다.

### 6.2 유효 성과 분석과 프로필 갱신 제안

중요도 높음 · 기획 상태 기획 확정

사용자는 충분히 지난 게시물의 유효 성과를 축·형식·제목 유형별로 분석해 다음 행동을 제안받는다. 수락한 제안은 프로필·제목 생성에 반영되고 성과에서 온 변경 이력은 3주 뒤 자동 제외된다. 발굴 추천 연계는 포함하지 않는다. 연계 FR: FR-IN-3·4·5·6.

**[기능의 근거]** 숫자를 보고도 다음 행동을 정하기 어려운 문제를 해결하려면 근거 있는 제안과 브랜드 프로필 반영이 필요하다.

**[성공 기준]** 유효한 표본만 근거로 최대 3개의 다음 행동을 제안하고, 수락한 변경의 3주 자동 제외를 보장한다.

**[개발 준비 슬롯]**

- **선행조건**:
  - 성과가 입력된 게시물이 있어야 한다.
  - 분석 대상 게시물은 게시 후 48시간이 지나야 한다.
- **트리거**: 사용자가 성과 분석을 열거나 프로필 갱신 제안을 수락한다.
- **동작**:
  - 앱은 도달 대비 저장률과 공유율을 축, 형식 및 제목 유형별로 계산한다.
  - 앱은 유효 수치만 근거로 최대 3개의 다음 행동을 제안한다.
  - 수락된 제안은 프로필과 제목 생성 입력에 반영한다.
- **결과**:
  - 분석 결과와 제안이 표시된다.
  - 수락한 변경은 성과에서 온 변경 이력으로 저장되고 3주 뒤 자동 제외된다.
- **예외**:
  - 분자 또는 분모가 비어 있으면 해당 계산에서 제외한다.
  - 표본이 3개 미만이면 결론을 제시하지 않는다.
  - 게시 후 48시간 전에는 집계 중으로 표시한다.
- **표시**:
  - 지표별 평균, 표본 상태 및 제안 근거를 표시한다.
  - 집계 중인 게시물을 구분해 표시한다.
- **권한 & 접근**: 로컬 사용자는 제안을 수락하거나 거절한다.
- **비즈니스 규칙**:
  - 없는 숫자와 빈 값은 평균 및 제안 근거에 사용하지 않는다.
  - 성과 기반 프로필 변경은 수락한 경우에만 적용한다.
  - 발굴 추천과의 연계는 이번 범위에서 제외한다.
- **데이터**:
  - 분석 결과는 대상 게시물, 지표, 분류값, 표본 수 및 계산 시각을 저장한다.
  - 프로필 변경 이력은 출처, 수락 시각 및 만료 시각을 저장한다.

## 7 로컬 우선 데이터 보호와 실패 처리

중요도 높음 · 기획 상태 기획 확정

사용자 자료와 생성 이력을 로컬 사용자 1명·브랜드 1개 환경에서 보호한다. AI 실행 실패·취소 또는 렌더링 오류가 생겨도 불완전한 결과를 확정하지 않는다. 다중 사용자 로그인, 클라우드 동기화 및 메일 연동은 포함하지 않는다. 연계 FR: FR-AC-1, FR-AI-4.

**수용 기준**

1. ○ 로컬 서버는 127.0.0.1에만 바인딩되고 Host·Origin 검사를 수행하며, 사용자 키와 토큰은 OS 키체인에 보관한다.
2. ✓ 사용자가 생성 작업을 취소하면 실행 중인 CLI 프로세스를 종료하고 cancelled 이력을 남긴다.
3. ✓ JSON 복구와 규칙·렌더링 재작성은 정해진 재시도 한도를 넘기지 않으며, 실패한 결과는 확정 데이터로 저장되지 않는다.
4. ○ AI 호출을 제외한 로컬 기능은 오프라인 상태에서도 사용할 수 있는지 확인할 수 있다.

### 7.1 로컬 작업공간과 안전한 결과 저장

중요도 높음 · 기획 상태 기획 확정

로컬 사용자는 로그인 없이 하나의 브랜드 작업공간에서 자료와 생성 이력을 관리한다. 사용자 자료는 로컬에서 처리하고 사용자 키·토큰은 OS 키체인에 보관한다. 클라우드 동기화·다중 사용자·다른 기기 사용은 포함하지 않는다. 연계 FR: FR-AC-1.

**[기능의 근거]** 이번 버전은 외부 계정 연동 없이 로컬에서 카드뉴스 기본 흐름을 완성하는 것을 목표로 한다.

**[개발 준비 슬롯]**

- **선행조건**: 로컬 앱 데이터 폴더와 OS 키체인을 사용할 수 있어야 한다.
- **트리거**: 사용자가 앱을 처음 실행하거나 로컬 데이터를 저장하는 동작을 시작한다.
- **동작**:
  - 앱은 로컬 사용자 1명과 브랜드 1개의 작업공간을 초기화한다.
  - 앱은 향후 이전을 위해 데이터에 user_id와 brand_id 칸을 유지한다.
- **결과**: 사용자 자료와 생성 이력이 로컬 작업공간에 저장된다.
- **예외**: 저장에 실패하면 확정 데이터로 기록하지 않고 실패 원인을 알린다.
- **표시**: 로그인 화면 없이 로컬 작업공간을 사용할 수 있음을 표시한다.
- **권한 & 접근**: 현재 컴퓨터의 로컬 사용자만 작업공간에 접근한다.
- **비즈니스 규칙**:
  - 이번 버전은 클라우드 동기화와 다중 사용자 기능을 제공하지 않는다.
  - 로컬 서버는 127.0.0.1에만 바인딩하고 Host와 Origin을 검사한다.
- **데이터**:
  - 작업 데이터는 user_id와 brand_id를 포함하는 로컬 레코드로 저장한다.
  - 사용자 키와 토큰은 OS 키체인에 저장한다.

### 7.2 생성 실패와 취소의 안전한 복구

중요도 높음 · 기획 상태 기획 확정

사용자는 AI 생성 또는 렌더링 작업의 실패와 취소를 안전하게 처리한다. 앱은 불완전한 결과를 확정 데이터로 남기지 않고 취소 이력과 오류 정보를 제공한다. 다시 열었을 때의 재진입 위치·임시 입력 보존 범위는 아직 결정하지 않았다. 연계 FR: FR-AI-4.

**[기능의 근거]** AI 실행과 렌더링 오류가 발생해도 반쯤 만들어진 결과가 저장되어 기본 흐름의 신뢰성을 해치지 않아야 한다.

**[개발 준비 슬롯]**

- **선행조건**: AI 생성 또는 렌더링 작업이 실행 중이어야 한다.
- **트리거**: 작업이 실패하거나 사용자가 취소를 선택한다.
- **동작**:
  - 앱은 취소 시 실행 프로세스를 종료한다.
  - 앱은 실패 또는 취소된 결과를 확정 저장에서 제외한다.
- **결과**:
  - 취소된 작업에는 cancelled 이력이 남는다.
  - 실패한 작업은 확정 결과를 만들지 않는다.
- **예외**:
  - 오래된 완료 작업 ID는 조용히 정리한다.
  - 실제 진행 작업이 사라진 경우에만 사용자에게 안내한다.
- **표시**: 실패 이유와 다음에 할 수 있는 행동을 한국어로 표시한다.
- **권한 & 접근**: 로컬 사용자는 자신이 시작한 작업을 취소할 수 있다.
- **비즈니스 규칙**: 불완전하거나 검증되지 않은 결과는 확정 데이터로 저장하지 않는다.
- **데이터**: 실행 이력은 상태와 취소 여부를 저장한다.

## 8 대외활동 공지와 마감 할 일 관리

중요도 높음 · 기획 상태 기획 작성중

사용자는 대외활동을 등록하고 공지를 직접 붙여넣거나 캡처로 제출해 할 일과 마감을 확인한다. 앱은 원문 인용을 붙인 제출 항목을 마감순으로 정리한다. 이메일 연동·공지 자동 수집은 이번 버전에서 하지 않는다. 연계 FR: FR-OP-1·2·4·5; 조건부 F이며 11월 29일까지 FR-IN-2~6이 끝나지 않으면 W로 옮긴다.

**수용 기준**

1. ○ 사용자는 활동 이름·기관·기간·담당 연락처·필수 표기를 저장하고 활동별 색 태그로 구분할 수 있다.
2. ○ 사용자는 공지를 붙여넣거나 캡처로 넣을 수 있고 두 경로 모두 같은 할 일 추출 단계로 이어지며 이메일 연결 경로는 보이지 않는다.
3. ○ 앱은 마감일시·제출물·형식/분량·필수 표기·제출 링크에 실제 원문 인용을 붙이고 상대 날짜를 풀 수 없으면 비워서 확인을 요청한다.
4. ○ 대시보드는 오늘·이번 주·다음 주의 마감, 활동별 필터·D-3 강조·완료 표시·제출 링크·마감 중복 주간 경고를 제공한다.

### 8.1 활동 등록과 공지 넣기

중요도 높음 · 기획 상태 기획 작성중

사용자는 대외활동 정보와 공지 원문을 등록하고 공지를 직접 붙여넣거나 캡처로 제공한다. 두 공지 입력은 같은 할 일 추출 단계로 이어진다. 이메일 계정 연결과 자동 공지 수집은 하지 않는다. 연계 FR: FR-OP-1·2; 조건부 F이며 11월 29일까지 성과 분석이 끝나지 않으면 W로 옮긴다.

**[기능의 근거]** 성장한 사용자가 흩어진 대외활동 공지를 놓치지 않으려면 활동과 원문을 같은 곳에서 관리해야 한다.

**[개발 준비 슬롯]**

- **선행조건**: 11월 29일까지 FR-IN-2~6 성과 분석이 완료돼 이번 버전의 조건부 운영 범위가 유지되어야 한다.
- **트리거**:
  - 사용자가 활동 정보를 등록한다.
  - 사용자가 활동에 공지 원문을 붙여넣거나 캡처를 올린다.
- **동작**:
  - 앱은 활동 이름·기관·기간·담당 연락처·필수 표기와 색 태그를 저장한다.
  - 앱은 붙여넣기와 캡처 공지를 같은 할 일 추출 단계로 보낸다.
- **결과**: 등록한 활동과 공지 원문이 할 일 추출의 입력으로 연결된다.
- **예외**: 캡처에서 읽지 못한 공지 내용은 추측하지 않는다.
- **표시**:
  - 활동별 색 태그와 붙여넣기·캡처 공지 입력을 표시한다.
  - 이메일 연결 진입점은 표시하지 않는다.
- **권한 & 접근**: 로컬 사용자는 자신의 활동과 공지만 등록할 수 있다.
- **비즈니스 규칙**:
  - 이번 버전에는 공지를 붙여넣거나 캡처로만 넣는다.
  - FR-IN-2~6이 11월 29일까지 완료되지 않으면 이 기능을 W로 옮기고 메뉴를 숨긴다.
- **데이터**:
  - 활동 기록은 이름·기관·기간·담당 연락처·필수 표기·색 태그를 갖는다.
  - 공지 기록은 입력 경로, 원문 또는 캡처 참조와 소속 활동을 갖는다.

### 8.2 공지 할 일 추출과 마감순 보기

중요도 높음 · 기획 상태 기획 작성중

사용자는 등록한 공지에서 원문 근거가 붙은 제출 할 일을 확인하고 마감순 대시보드에서 관리한다. 마감일을 풀 수 없는 항목은 사람이 확인하도록 남겨 두고 제출을 자동 처리하지 않는다. 이메일을 읽거나 자동 제출하는 경로는 포함하지 않는다. 연계 FR: FR-OP-4·5; 조건부 F이며 11월 29일까지 성과 분석이 끝나지 않으면 W로 옮긴다.

**[기능의 근거]** 대외활동 공지의 마감·제출물·필수 표기가 흩어지면 사용자가 다음 행동을 놓치기 쉽다.

**[성공 기준]** 운영 범위가 유지되는 경우 공지 30건에서 마감일 추출 정확도 90% 이상을 검증한다.

**[개발 준비 슬롯]**

- **선행조건**:
  - 등록된 활동에 사용자가 제공한 공지 원문이 있어야 한다.
  - 11월 29일까지 FR-IN-2~6 성과 분석이 완료돼 이번 버전의 조건부 운영 범위가 유지되어야 한다.
- **트리거**:
  - 사용자가 등록한 공지의 할 일 추출을 요청한다.
  - 사용자가 마감순 대시보드를 연다.
- **동작**:
  - 앱은 공지 원문에서 마감일시·제출물·형식과 분량·필수 표기·제출 링크를 추출하고 각각에 실제 원문 인용을 붙인다.
  - 앱은 마감일별 오늘·이번 주·다음 주의 할 일을 활동 필터와 함께 정리한다.
- **결과**: 사용자는 근거가 표시된 할 일과 마감순 목록을 확인하고 완료로 표시할 수 있다.
- **예외**: 공지 작성일 기준으로 상대 날짜를 풀 수 없으면 마감일을 비워 두고 사용자 확인을 요청한다.
- **표시**:
  - 대시보드는 오늘·이번 주·다음 주와 활동 필터·D-3 강조·완료 표시·제출 링크를 보여 준다.
  - 마감이 겹치는 주는 경고하고 날짜를 풀 수 없는 할 일은 확인이 필요함을 표시한다.
- **권한 & 접근**: 로컬 사용자는 자신의 활동에서 추출한 할 일의 확인·완료 표시를 할 수 있다.
- **비즈니스 규칙**:
  - 제출 전 사용자는 공지 원문과 기한을 직접 확인한다.
  - FR-IN-2~6이 11월 29일까지 완료되지 않으면 이 기능을 W로 옮기고 메뉴를 숨긴다.
- **데이터**: 할 일은 공지 참조, 마감일시, 제출물, 형식과 분량, 필수 표기, 제출 링크, 각 항목의 인용 및 완료 상태를 연결한다.
